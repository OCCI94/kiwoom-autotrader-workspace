# 변경 기록 양식 (6항목)

arm 코드·파라미터·프롬프트·설정을 바꾸기 전에 쓴다. 기록이 없으면 SHADOW 등록도, 배포 창 요청도 하지 않는다. 파일은 봇 소스 트리 밖(예: `reports/<날짜>/arm-change-<이름>.md`)에 두고, 레지스트리 `evidence`에서 경로로 가리킨다.

```
# arm 변경 기록: <게이트 이름>

- 분류: 결함 수정 | 경제적 변경 | 결함 수정(경제적 부수효과 있음)
- 대상 arm: ...
- 영향 경로(file:line, 검토 시점 mtime):
  1. ...
- 소스 manifest/SHA: ...
- 상태 전환: (없음)→SHADOW | SHADOW→LIVE | ...→OFF

## 1. 목적
무엇이 잘못됐거나 무엇을 바꾸려 하는가. 문서/설계가 말하는 것과 코드가 하는 것의 차이를 한 문장으로.

## 2. 기대 효과와 측정 지표
무엇이 어떻게 달라질 것으로 기대하는가. 지표는 원장에서 셀 수 있는 것만(건수·비율·금액). "좋아진다"는 지표가 아니다.

## 3. 측정 방법과 기간
어느 테이블·열을 어떤 쿼리로 세는가, 며칠 또는 몇 건까지 보는가, SHADOW 만료일은 언제인가. 비교 기준(변경 전 같은 기간)도 적는다.

## 4. 롤백 절차
코드·설정을 어느 백업(경로·해시)으로 되돌리는가, 어느 창에서 하는가. 원장은 되돌리지 않는다. 롤백도 배포이므로 창·승인·claim이 든다.

## 5. 위험
실패 모드와 그때 생기는 손실·오염(원장 열, 상태 값, 주문 잔존). 각 위험에 감지 방법 한 줄.

## 6. 승인자 / 승인 시각
누가, 언제(KST), 무엇을(소스 수리 / SHADOW 배포 / LIVE 승격 / 예외 토큰) 승인했는가. 수리 승인과 배포 승인을 따로 적는다.
```

## 작성 예: 2026-11-03 단일가 매수 TTL 수정 (예시 값은 「예시」로 표시)

```
# arm 변경 기록: EXP_D/auction_window_ttl

- 분류: 결함 수정(경제적 부수효과 있음)
- 대상 arm: EXP_D, EXP_VSS, EXP_LDR (C·GDR은 180초와 창 종료 중 이른 시각을 유지)
- 영향 경로(file:line, 2026-11-03 소스 기준 — 재검토 시 다시 찾을 것):
  1. kiwoom_autotrader/trading/paper_experiment_rules.py:401  15:20~15:30 closing_auction 판정
  2. kiwoom_autotrader/trading/paper_experiment_monitor.py:399  auction_intent → 단일가 지정가 매수
  3. kiwoom_autotrader/telegram/listener.py:591  수신기 TTL tick(기본 180초)
  4. kiwoom_autotrader/config/settings.py:210  unfilled_buy_ttl_seconds 기본값 180
  5. kiwoom_autotrader/trading/execution_log.py  orders.registered_at 기준으로 만료 계산, 취소 결과 기록
  6. UNFILLED_BUY_TTL.md "현재 공통 계약 (2026-11-03)"  문서 측 계약
- 소스 manifest/SHA: reports/2026-11-03/<시각>-full-…-source-manifest.json (예시 경로)
- 상태 전환: (없음)→SHADOW (예시; 실제로는 미배포)

## 1. 목적
D·VSS·LDR은 15:20~15:30 종가 단일가 창에 지정가 매수를 넣고 15:30 체결을 기다리는 arm인데, 공통 TTL 180초가 15:23쯤 주문을 취소해 단일가에 참여하지 못했다. 문서(PAPER_EXPERIMENT.md의 진입 정의)와 코드(180초 일괄 TTL)가 어긋난 결함이다. 수정: 원 주문 판단 해시에 연결된 유효 창 종료(15:30)를 만료로 쓰고, 창 근거가 없거나 무효이면 180초를 유지한다.

## 2. 기대 효과와 측정 지표
- TTL 사유 취소 건수(15:20~15:30 접수, arm ∈ {EXP_D, EXP_VSS, EXP_LDR}): 변경 전 거의 전부 → 변경 후 0.
- 같은 주문의 단일가 체결 건수와 체결률(fills / orders).
- 15:30 이후에도 남은 미체결 주문 수(취소 경로가 정상 동작하면 0으로 수렴).
- 부수효과 지표: 해당 arm 포지션 수·예산 소진(PAPER_EXPERIMENT.md 한도 내인지).

## 3. 측정 방법과 기간
- 원장 복사본(mode=ro)에서 orders·fills·order_decisions를 arm·접수시각으로 묶어 일별 집계. 관측 테이블은 보조.
- SHADOW 기간: 배포일부터 10거래일 또는 arm별 단일가 주문 30건 중 먼저 오는 쪽. 만료일 2026-11-20(예시).
- 비교 기준: 변경 전 10거래일의 같은 집계.

## 4. 롤백 절차
- 배포 직전 백업(runtime·설정 경로와 SHA-256, 배포 보고에 기록된 값)으로 코드·설정만 복원.
- 다음 정상 창(화·목)에서 수행하며 claim 1회를 쓴다. 긴급 시 예외 토큰.
- 원장은 복원하지 않는다. 롤백 뒤 state.json 5개 값 확인.

## 5. 위험
- 창 근거 검증 오류로 180초로 되돌아가 효과가 없음 → 지표 1이 0이 아니면 감지.
- 15:30 이후 취소 경로 실패로 주문 잔존 → 지표 3, 수신기 10분 주기 미해결 정산 로그.
- 15:30에 취소·조회가 몰려 공용 큐 지연 → 배치 소요 시간 상태 값.
- 배포 도구 결함으로 창을 낭비(2026-11-03 실제 발생) → 창 전에 런타임 복사본 리허설.

## 6. 승인자 / 승인 시각
- 소스 수리·격리 검증: 사용자, 2026-11-03 (장후). 코드 배포 승인이 아님.
- 배포: 2026-11-03 야간 예외 토큰으로 3회 시도, 전부 배포 도구 결함으로 실패·미확정(claim 소비). 재배포는 새 토큰 또는 2026-11-05(목) 정상 창에서 별도 승인 — 승인 시각 미기재.
- SHADOW→LIVE: 미승인.
```
