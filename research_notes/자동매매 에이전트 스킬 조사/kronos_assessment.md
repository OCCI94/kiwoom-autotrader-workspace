# Kronos (shiyu-coder/Kronos) 평가 — 키움 모의투자 규칙 봇 관점

작성 2026-11-04. 대상 독자: 키움 REST 모의투자 규칙 기반 봇(13 EXP arm + S5, 1분·일봉, SQLite 원장) 운영자. 전제 규칙: ~200 트레이드 + 봉인 holdout 엣지 판정 전에는 LLM/ML을 라이브 주문 경로에 넣지 않으며, ML은 전부 야간 오프라인이다. 표기: **[확인]** = 저장소·논문·모델카드·이슈 본문에서 읽은 사실, **[주장]** = 저자 또는 제3자 자가 보고 수치. 클론·가중치 다운로드·코드 실행은 하지 않았다.

## 1. 정체

- **무엇인가 [확인]**: OHLCV(A) K-line 전용 파운데이션 모델. 1단계 토크나이저가 연속 OHLCVA(6차원)를 Binary Spherical Quantization(LFQ 변형)으로 20bit 코드(coarse 10bit + fine 10bit, 각 2^10 항목)로 이산화하고, 2단계 decoder-only autoregressive Transformer가 토큰을 다음-토큰 예측으로 사전학습한다. 토크나이저 인코더/디코더는 각 3층 d=256. 시간 임베딩은 minute/hour/weekday/day/month — [arXiv HTML 2508.02739v1](https://arxiv.org/html/2508.02739v1); [README](https://github.com/shiyu-coder/Kronos).
- **출력 [확인]**: `predict()`는 `y_timestamp`에 대한 open/high/low/close/volume/amount DataFrame 한 개를 돌려준다. `sample_count` 경로를 생성한 뒤 `np.mean`으로 평균한 단일 경로이며 분포·분위수는 반환하지 않는다("확률적 예측"은 샘플링 과정에 있지 API 출력에는 없다) — [model/kronos.py](https://raw.githubusercontent.com/shiyu-coder/Kronos/master/model/kronos.py); 이슈 #415도 같은 지적 — [#415](https://github.com/shiyu-coder/Kronos/issues/415).
- **모델 크기 [확인]**: mini 4.1M(ctx 2048, Tokenizer-2k), small 24.7M(8층 d512, ctx 512), base 102.3M(12층 d832, ctx 512), large 499.2M(18층 d1664, **비공개**, 이슈로 접근 요청만 쌓임 #349/#360/#406/#416/#426) — [README 모델 동물원](https://github.com/shiyu-coder/Kronos); [HF Kronos-base](https://huggingface.co/NeoQuasar/Kronos-base); [HF Kronos-mini](https://huggingface.co/NeoQuasar/Kronos-mini); [이슈 목록](https://github.com/shiyu-coder/Kronos/issues?q=is%3Aissue+sort%3Aupdated-desc).
- **사전학습 데이터 [확인/불일치]**: 초록은 "45개 거래소 120억+ K-line", 부록 B는 "40개+ 거래소 30개국+", 표 13은 약 96,569 자산·12.11B 관측, 주기 1분~주봉(서론 "7개 주기" vs 부록 B 필터표 12개), 자산군 주식·암호화폐·선물·FX. 컷오프 2024-06, 테스트는 2024-07부터. **XKRX(한국거래소) 포함: 주식/ETF 2,928개, 205,061,301 관측, 주기 5분~주봉, 시작 2020-01-31** — 즉 한국 1분봉은 사전학습에 없다 — [arXiv HTML 2508.02739v1 표 13·부록 B·D](https://arxiv.org/html/2508.02739v1). 데이터 벤더·거래소 전체 목록은 미공개, 학습 데이터 미공개 [확인, #265 댓글](https://github.com/shiyu-coder/Kronos/issues/265).
- **학습 컴퓨트 [확인]**: 8×RTX 4090D 포드 3개(24장). GPU-시간·스텝 수 미기재 — [arXiv HTML](https://arxiv.org/html/2508.02739v1).
- **저자·소속 [확인]**: Yu Shi, Zongliang Fu, Shuo Chen, Bohan Zhao, Wei Xu, Changshui Zhang, Jian Li — 칭화대 IIIS·자동화과 — [arXiv abs](https://arxiv.org/abs/2508.02739). arXiv v1 2025-08-02(q-fin.ST), 이후 버전 없음. README 뉴스: 2025-11-10 AAAI 2026 채택 — [README](https://github.com/shiyu-coder/Kronos); NeurIPS 2025 워크숍("Have We Reached the BERT Moment?") 포스터 — [neurips.cc](https://neurips.cc/virtual/2025/130441).

## 2. 사용법

- **설치 [확인]**: Python 3.10+, `pip install -r requirements.txt`(numpy, pandas==2.2.2, torch>=2.0.0, einops==0.8.1, huggingface_hub==0.33.1, matplotlib, tqdm, safetensors==0.6.2) — [requirements.txt](https://raw.githubusercontent.com/shiyu-coder/Kronos/master/requirements.txt). 이 프로젝트 스킬 스크립트는 시스템 python 3.9.6 stdlib 기준이므로 Kronos는 봇과 분리된 별도 venv(3.10+)에서만 돌려야 한다.
- **추론 API [확인]**: `KronosPredictor(model, tokenizer, device=None, max_context=512, clip=5)`; `device=None`이면 cuda:0 → mps → cpu 순 자동 선택(2025-12-20 커밋). `predict(df, x_timestamp, y_timestamp, pred_len, T=1.0, top_k=0, top_p=0.9, sample_count=1, verbose=True)`; df 필수 열 open/high/low/close, volume/amount 선택(배치에서는 0 채움). 정규화는 **lookback 창만의** 열별 z-score 후 ±5 클립, 역정규화 후 반환. `predict_batch(df_list, ...)`는 동일 lookback·pred_len 요구. 자기회귀 루프는 pred_len 스텝을 s1→s2 토큰 순으로 1스텝씩 생성, 512 초과 시 슬라이딩 윈도. `top_k>0`이면 `top_p` 무시 — [model/kronos.py](https://raw.githubusercontent.com/shiyu-coder/Kronos/master/model/kronos.py). 예제는 lookback 400 / pred_len 120 / T 1.0 / top_p 0.9 / sample_count 1, 데이터 XSHG 600977 5분봉 — [examples/prediction_example.py](https://raw.githubusercontent.com/shiyu-coder/Kronos/master/examples/prediction_example.py). 논문 부록 E 권고: 예측은 T≈0.6·낮은 top_p, 변동성·생성은 T≈1.0·top_p≥0.9 [확인] — [arXiv HTML](https://arxiv.org/html/2508.02739v1). 파인튜닝 설정은 T 0.6 / top_p 0.9 / sample_count 5 — [finetune/config.py](https://raw.githubusercontent.com/shiyu-coder/Kronos/master/finetune/config.py).
- **미해결 추론 결함(2026-11-04 기준 모두 open) [확인]**: (1) `KronosPredictor`가 `eval()`을 호출하지 않아 pinned `huggingface_hub==0.33.1`(<1.9.0)에서는 드롭아웃(small 0.25/0.1, base 0.2)이 켜진 채 추론, s2 헤드가 샘플된 s1을 무시 — [#415](https://github.com/shiyu-coder/Kronos/issues/415); 수정 PR #382(2026-08-04)·#407 미머지 — [PR #382](https://github.com/shiyu-coder/Kronos/pull/382), [PR 목록](https://github.com/shiyu-coder/Kronos/pulls). (2) `decode_s2` 단일 쿼리 교차어텐션에서 rotary 위치가 0으로 붕괴(학습/추론 불일치), PR #425(2026-11-01) open — [#423](https://github.com/shiyu-coder/Kronos/issues/423). (3) CPU와 GPU 결과가 같은 시드에서도 다름(관리자: "둘 다 유효한 샘플") — [#184](https://github.com/shiyu-coder/Kronos/issues/184). (4) 정규화·클립 때문에 첫 예측봉이 마지막 입력과 불연속, 관리자 제안 `x_std+100` 트릭은 "체계적으로 검증 안 됨" — [#26](https://github.com/shiyu-coder/Kronos/issues/26). 저장소 자체 회귀 테스트는 CPU·eval()·시드 123·top_k=1·모델 revision 고정으로 돌린다 — [tests/test_kronos_regression.py](https://raw.githubusercontent.com/shiyu-coder/Kronos/master/tests/test_kronos_regression.py). 쓰려면 커밋·revision 고정 + `eval()` 로컬 패치가 전제다.
- **파인튜닝 파이프라인 [확인]**: `finetune/`(Qlib 기반, 일봉 전제): `config.py`에 instrument csi300, 데이터 2011-01-01~2025-06-05, train ~2022-12-31, **val 2022-09-01~2024-06-30(train과 4개월 겹침)**, test 2024-04-01~, backtest 2024-07-01~2025-06-05, lookback 90 / predict 10, epochs 30, batch 50/GPU, 토크나이저 LR 2e-4·예측기 4e-5; 실행은 `torchrun --nproc_per_node=NUM_GPUS train_tokenizer.py` → `train_predictor.py` → `qlib_test.py --device cuda:0` — [finetune/config.py](https://raw.githubusercontent.com/shiyu-coder/Kronos/master/finetune/config.py); [README](https://github.com/shiyu-coder/Kronos). `qlib_test.py`: 신호 = 예측 종가(last/mean/max/min) − 현재 종가, Qlib TopkDropoutStrategy(hold 50, drop 5, hold_thresh 5), 체결 open가, `delay_execution=True`, 비용 open 0.1%/close 0.15%/min 5, 상한 9.5% — [finetune/qlib_test.py](https://raw.githubusercontent.com/shiyu-coder/Kronos/master/finetune/qlib_test.py). `finetune_csv/`(CSV: timestamps/open/high/low/close/volume/amount; 예제 HK 09988 5분봉, lookback 512 / predict 48, tokenizer 30ep + base 20ep, batch 32, train 0.9/val 0.1/test 0.0, `use_cuda: true`, DDP nccl/gloo, 예제 `--nproc_per_node=8`) — [finetune_csv/README.md](https://raw.githubusercontent.com/shiyu-coder/Kronos/master/finetune_csv/README.md); [예제 yaml](https://raw.githubusercontent.com/shiyu-coder/Kronos/master/finetune_csv/configs/config_ali09988_candle-5min.yaml). README 경고: A주 예제는 "production-ready 아님", `finetune/` 주석 다수가 Gemini 2.5 Pro 생성이라 부정확할 수 있음 — [README](https://github.com/shiyu-coder/Kronos). 최소 데이터량·VRAM·학습 시간은 어디에도 없다 [확인].
- **파인튜닝 누출 이력 [확인]**: #227(2026-03-17) 창 전체(lookback+horizon)로 평균·표준편차 계산 → 관리자 #228에서 "finetune 코드의 실제 문제, lookback만으로 계산해야" 인정 → PR #234(2026-04-13 머지)가 `finetune/dataset.py`만 수정. #422(2026-10-29)는 `finetune_csv/finetune_base_model.py`가 여전히 창 전체 통계라고 지적(내가 코드로 재확인하지 않음) — [#227](https://github.com/shiyu-coder/Kronos/issues/227); [#228](https://github.com/shiyu-coder/Kronos/issues/228); [#422](https://github.com/shiyu-coder/Kronos/issues/422).
- **Web UI [확인]**: Flask, `python run.py` → localhost:7070, CSV/Feather 업로드, 창 520(400+120) 고정, mini/small/base 선택, T 0.1~2.0(권장 1.2~1.5), top_p, 샘플 1~5, 디바이스 CPU/CUDA/**MPS("Mac 사용자 권장")**; 의존성 flask 2.3.3, plotly 5.17, torch>=2.1 — [webui/README.md](https://raw.githubusercontent.com/shiyu-coder/Kronos/master/webui/README.md); [webui/requirements.txt](https://raw.githubusercontent.com/shiyu-coder/Kronos/master/webui/requirements.txt).

## 3. 증거

- **논문 벤치마크 [주장]**: 제로샷 가격 예측 RankIC가 최강 TSFM 대비 +93%, 최강 비사전학습 베이스라인 대비 +87%; 변동성 MAE −9%; 합성 K-line 충실도 +22% — [arXiv abs](https://arxiv.org/abs/2508.02739). 절대값(표 14·15, 주기 평균): RankIC small 0.0254 / base 0.0258 / large 0.0267, IC 0.0431/0.0435/0.0440; TimesNet RankIC 0.0143, PatchTST 0.0087, TimesFM 0.0021, Chronos-large 0.0078. 즉 "93% 개선"의 절대 크기는 RankIC 0.013 → 0.025 수준 — [arXiv HTML](https://arxiv.org/html/2508.02739v1). 평가 유니버스: 거래소 9곳(in-dist XSHG/XNAS/XJPX/XNSE/**XKRX**/XHKG, OOD XIDX/XKLS/XTAI) + Binance 현물 + FX 1,000+쌍; 표 8 lookback/horizon: 5분 480/96 … 일봉 40/12; IC·RankIC는 4개 가격 채널 평균, 주기 평균만 보고 → **일봉 단독·XKRX 단독 수치 없음** [확인]. 베이스라인 18개(본문 "25"와 불일치) [확인].
- **백테스트 [주장]**: 중국 A주만. 롱온리 top-k/drop-n 등가중, 최소 보유 5일, 비용 0.15%/trade, 신호 = H=10 평균 예측가 vs 종가, lookback 90. 표 10: large CSI300 AER 0.2193/IR 1.4177, CSI800 0.1974/1.8805; base 평균 0.1889/1.5217; small 0.1789/1.4222; Moment-large 0.1681/1.3677; PatchTST 0.1455/1.2464. **기간·Sharpe·MDD·신뢰구간·유의성 미보고** [확인] — [arXiv HTML](https://arxiv.org/html/2508.02739v1). 시간 분리는 사전학습 ≤2024-06 / 테스트 ≥2024-07로 명시 [확인], 그러나 사전학습 정규화 창(lookback만 vs 타깃 포함)은 논문·README 어디에도 없다 [확인].

## 4. 이 프로젝트에 맞는 쓰임 / 안 맞는 쓰임

| 용도 | 판정 | 참이어야 하는 것(데이터·컴퓨트·평가 설계) | 노력 | 사전등록 성공 기준(제안) |
|---|---|---|---|---|
| (a) 야간 오프라인 국면·변동성 예측을 **기록 전용 지표**로(§0-A 7 방식, 주문에 절대 미사용) | 조건부 가능, 그러나 지금은 아님 | 데이터: 코스피/코스닥 지수 또는 대표 ETF 일봉 ≥400봉(키움 일봉 API, 컷오프 = 마지막 마감 세션). 컴퓨트: small, MPS/CPU, lookback 40~400·pred_len 12·sample_count 5~30 → 종목당 ≈1분 [주장 #66], 지수 2~5개면 야간 10분 내. 평가: 실현변동성(식 12 방식) MAE를 EWMA·GARCH·HAR-RV 베이스라인과 비교(#269가 권한 대조군), ≥120거래일 누적 후 판정; 구간 커버리지(90% 밴드)도 기록. 전제: 커밋·HF revision 고정, `eval()` 패치, 시드 고정, `predict()` 평균이 아니라 샘플 경로 전부 저장(코드 수정 필요). | 스크립트 1~2일 + 6개월 누적 | H=5·10 실현변동성 MAE가 EWMA보다 낮은 날 비율 ≥60% **그리고** Diebold-Mariano p<0.05(설정 조합 수 N으로 Holm 보정) **그리고** 90% 밴드 커버리지 80~95%. 미달이면 지표 폐기. |
| (b) 익일 pre-list 후보 순위를 기존 결정론 스크리너와 **봉인 holdout**에서 비교 | 1단계 #5/#6 이후 실험 후보 | 데이터: 스크리너 유니버스(수십~수백 종목) 일봉 ≥90봉, 매일 마감 후 실행. 신호: H=5·10 평균 예측가/종가 −1 교차순위(논문 백테스트와 같은 정의, last/mean/max/min 네 변형은 각각 시도 1회로 등록). 평가: 다음날 시가 진입·H일 종가 청산 가정, 비용 = 수수료 왕복 + 매도세 0.2%(로드맵 기록), 순비용 RankIC와 Newey-West t; 기존 스크리너 점수에 회귀한 잔차 IC; #375 추정대로 t=2에 ≈166 리밸런스 → 일별 리밸런스 8개월, 뒤 1/3은 봉인. 다중검정: 시도 수 = 변형 4 × T 2 × lookback 2 = 16 → Holm 또는 DSR. | 구축 2~3일, 판정까지 8개월+ | 봉인 holdout에서 순비용 RankIC t ≥ 2(Holm, N=16) **그리고** 기존 스크리너 대비 잔차 IC t-stat 유지율 ≥50% **그리고** 상위 5 리밸런스 제외 후에도 순수익 >0. 하나라도 실패 → KILL, 재등록 없이 재시도 금지. |
| (c) 키움 1분봉으로 파인튜닝 | **지금 아님**(1단계 후 (b) 통과 시 재검토) | 데이터: 사전학습에 XKRX 1분봉 없음(5분~주봉) → 분포 밖. 필요량 미문서; 저장소 데모 규모는 CSI300 일봉 12년(≈0.9M봉) 또는 HK 1종목 5분봉; 1분봉 40종목×390봉×250일 ≈ 3.9M봉/년이면 규모는 비슷하나 토크나이저까지 재학습하면 base 가중치와 비교 불가. 누출: `finetune_csv`가 창 전체 통계 사용 가능성(#422, 코드 미확인), `finetune/config.py` train/val 4개월 겹침, 1분봉 중 수정주가·VI·동시호가 구간 처리 규약 없음. 컴퓨트: README는 torchrun 다중 GPU만, 관리자 "분봉은 ≈8 GPU" [주장], Mac 학습 시간 미문서. | 데이터 정제 1주 + GPU 임대 + 검증 설계 → 수 주 | 파인튜닝 전 (b)가 PROMOTE여야 착수. 착수 시 기준: 봉인 holdout에서 제로샷 base 대비 순비용 RankIC 개선이 bootstrap 95% CI에서 0을 제외. |
| (d) 장중 주문 판단(진입·청산·사이징) | **불가(하드 룰)** | 규칙 자체로 금지. 추가 근거: 미해결 추론 결함(#415/#423), CPU·GPU 비결정성(#184), 종목당 ≈1분 지연 [주장], 90% 밴드 실제 커버 58%(#375)·0.25(#269)의 보정 불량, RankIC 0.02대 vs 매도세 0.2%. | — | 1단계 200트레이드·봉인 holdout 판정 통과 전 재논의 금지. |
