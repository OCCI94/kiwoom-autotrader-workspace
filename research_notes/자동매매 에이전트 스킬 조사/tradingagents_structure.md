## 2. 실행 흐름

**진입** [확인, `tradingagents/graph/trading_graph.py`]: `TradingAgentsGraph(selected_analysts=("market","social","news","fundamentals"), debug=False, config=None, callbacks=None)`. 생성자는 `create_tier_client("deep"/"quick").get_llm()`으로 `deep_thinking_llm`·`quick_thinking_llm`을 만들고, `TradingMemoryLog`, `ConditionalLogic(max_debate_rounds, max_risk_discuss_rounds)`, `Propagator`, `Reflector(quick_llm)`를 준비한 뒤 `2*max_tool_rounds+2 < max_recur_limit`를 검사(아니면 `ValueError`), `GraphSetup.setup_graph(selected_analysts, memory_node=self._memory_step)`를 컴파일한다.
`propagate(company_name, trade_date, asset_type="stock", portfolio=None)` → `_validate_trade_date`(정확히 `YYYY-MM-DD`, 미래 날짜 금지) → `run_config(config)` + `checkpoint_scope` → `_run_graph`(`create_run_state` → `graph.invoke` 또는 debug 시 `stream_run` → `record_decision` → `clear_checkpoint_on_success`) → **반환 `(final_state, signal)`**, `signal = run_rating(final_state)`이며 파싱 불가 시 `"REVIEW"`. `main.py`는 `_, decision = ta.propagate("NVDA", "2026-09-01")`로 두 번째 값만 쓴다 [확인].

**그래프 토폴로지** [확인, `graph/setup.py`, `graph/conditional_logic.py`]:
1. `START` → 선택된 분석가 서브그래프 전부 + `"Memory Log"` 노드가 **병렬** 실행(v0.5.2부터; CHANGELOG). 각 분석가는 자기 report 키만 반환해 쓰기 충돌을 피한다.
2. fan-in → `"Bull Researcher"`. `should_continue_debate`: `investment_debate_state["count"] >= 2*max_debate_rounds`면 `"Research Manager"`, 아니면 `current_response`가 "Bull"로 시작하면 `"Bear Researcher"`, 그 외 `"Bull Researcher"`. 기본 1라운드 = Bull 1턴 + Bear 1턴.
3. `"Research Manager"` → `"Trader"` → `"Aggressive Analyst"`. `should_continue_risk_analysis`: `risk_debate_state["count"] >= 3*max_risk_discuss_rounds`면 `"Portfolio Manager"`, 아니면 `latest_speaker` Aggressive→`"Conservative Analyst"`, Conservative→`"Neutral Analyst"`, 그 외→`"Aggressive Analyst"`. 기본 1라운드 = 3턴.
4. `"Portfolio Manager"` → `END`. (README가 말하는 "Risk Judge/시뮬레이션 거래소"는 코드에 없다; PM 노드가 `latest_speaker="Judge"`를 기록할 뿐 [확인].)

**분석가 서브그래프** [확인, `graph/setup.py`, `graph/analyst_execution.py`, `agents/analysts/turn.py`]: 툴이 있는 분석가는 `agent` → `tools`(LangGraph `ToolNode`) → `agent` … 루프, `max_tool_rounds`(기본 20) 소진 시 `WRAP_UP` 휴먼 메시지("you have used every tool round this report allows")를 넣고 툴 바인딩 없이 1회 더 호출해 리포트를 강제. `ANALYST_NODE_SPECS`: `market`→`"Market Analyst"`/`market_report`/`TOOLS=(get_stock_data, get_indicators, get_verified_market_snapshot)`; `social`→`"Sentiment Analyst"`/`sentiment_report`/**툴 없음**(모델 호출 전에 코드가 직접 `get_news.func`·`fetch_stocktwits_messages(limit=30)`·`fetch_reddit_posts`를 7일 창으로 가져와 프롬프트에 삽입, `jev_screen` 적용); `news`→`"News Analyst"`/`news_report`/`(get_news, get_global_news, get_macro_indicators, get_prediction_markets)`; `fundamentals`→`"Fundamentals Analyst"`/`fundamentals_report`/`(get_fundamentals, get_balance_sheet, get_cashflow, get_income_statement, get_insider_transactions)`. Market Analyst 프롬프트: 12개 지표(`close_50_sma, close_200_sma, close_10_ema, macd, macds, macdh, rsi, boll, boll_ub, boll_lb, atr, vwma`) 중 최대 8개 선택, 보고 전 반드시 `get_verified_market_snapshot`을 호출해 "정확한 OHLCV·가격·지표 수치의 단일 진실"로 삼고 다른 툴 출력과 충돌하면 새 숫자로 합치지 말고 **불일치를 표기**하라고 지시 [확인, `agents/analysts/market_analyst.py`].

**LLM 티어 배정** [확인, `graph/setup.py`]: quick = 분석가 4종, Bull/Bear Researcher, Trader, Aggressive/Neutral/Conservative Analyst, Reflector; deep = Research Manager, Portfolio Manager. 기본값 `deep_think_llm="gpt-6-sol"`, `quick_think_llm="gpt-6-luna"`, 티어별 프로바이더 분리 가능(`deep_think_provider`/`quick_think_provider`, v0.6.0) [확인, `default_config.py`, `llm_clients/model_catalog.py`].

**상태 스키마** [확인, `agents/state.py`]: `AgentState(MessagesState)`: `company_of_interest, asset_type, instrument_context, trade_date, market_report, sentiment_report, news_report, fundamentals_report, investment_debate_state, investment_plan, trader_investment_plan, risk_debate_state, final_trade_decision, final_rating("REVIEW" 가능), past_context, memory_note, portfolio_context`. `InvestDebateState`: `bull_history, bear_history, history, current_response, count`. `RiskDebateState`: `aggressive_history, conservative_history, neutral_history, history, latest_speaker, current_{aggressive,conservative,neutral}_response, count`. 초기값은 `graph/propagation.py` `create_initial_state`(모두 `""`/`count=0`, `messages=[("human", company_name)]`), 실행 인자 `recursion_limit=max_recur_limit(100)`, `stream_mode="values"`.

**각 노드의 입·출력** [확인]: Bull/Bear(`agents/researchers/*.py`)는 4개 리포트 + `history` + 상대의 `current_response`를 f-string 프롬프트로 받아 `llm.invoke` 1회, `"Bull Analyst: …"`를 `history`/`bull_history`에 append, `count+=1`; 과거 메모리는 읽지 않음. Research Manager(`agents/managers/research_manager.py`)는 토론 `history`를 받아 `bind_structured(llm, ResearchPlan)`로 `investment_plan` 생성. Trader(`agents/trader/trader.py`)는 `investment_plan`+`market_report`+포트폴리오 컨텍스트로 `TraderProposal`(Action Buy/Hold/Sell, Entry/Stop을 "절대 가격, 예: 189.5", Position Sizing) 1회 호출, 툴 없음(`NO_EXTERNAL_TOOLS`). Risk 3인(`agents/risk_mgmt/*_debator.py`)은 `trader_investment_plan`+리포트+상대 발언을 받아 "대화체·서식 없이" 1회씩. Portfolio Manager(`agents/managers/portfolio_manager.py`)는 risk `history`+`investment_plan`+`trader_investment_plan`+`past_context`(비어있지 않을 때만 "Lessons from prior decisions and outcomes")로 `PortfolioDecision` 생성, `final_rating = decision.rating.value`. RM·PM 공통 프롬프트 문장: "conflict alone is not a reason to Hold", "Commit to the stronger case, sized by how decisively it wins", "Choose Hold only when the evidence is still balanced after that weighing, or too thin to support a call", "independent of speaking order".

**구조화 출력과 rating** [확인, `agents/schemas.py`, `agents/structured.py`, `agents/rating.py`]: `PortfolioRating` StrEnum `Buy/Overweight/Hold/Underweight/Sell`, `TraderAction` `Buy/Hold/Sell`, `SentimentBand` 6단계; `ResearchPlan(recommendation, rationale, strategic_actions)`, `TraderProposal(action, reasoning, entry_price?, stop_loss?, position_sizing?)`, `PortfolioDecision(rating, executive_summary, investment_thesis, price_target?, time_horizon?)`, `SentimentReport(overall_band, overall_score 0~10, confidence low/medium/high, narrative)`. `bind_structured`는 `llm.with_structured_output(schema)`; `NotImplementedError/AttributeError`면 `None`. `invoke_structured_or_freetext`는 구조화 실패(예외·`None` 파싱) 시 **같은 프롬프트로 평문 1회** 재호출하고 끝. 평문은 `extract_rating` 정규식(NFKC 정규화, "Rating:" 라벨/첫 줄 rating, 범례 줄 무시, 복수 라벨이 불일치하면 `None`)으로 파싱, `parse_rating(default=RATING_REVIEW)`. 구조화 출력이 성공해도 `final_rating` 값 자체는 티어 집합과 재검증하지 않는다.

**LLM 호출 수(실행 1회, 기본 설정)**: 코드 구조상 최소 = 분석가 4(각 ≥1, 툴 루프마다 +1) + Bull 1 + Bear 1 + RM 1 + Trader 1 + Risk 3 + PM 1 ≈ **12회 + 분석가 툴 라운드**, 정산 시 settled 결정 1건당 Reflector 1회 추가 [확인, 그래프 구조에서 계산]. 이슈 #750(2026-05-06) 작성자 주장 16~22회/실행, 2026-11-01 댓글 "v0.7.1, DeepSeek, 분석가 1·토론 1·리스크 1 → 약 13회, ¥0.15~0.28" [주장] — https://github.com/TauricResearch/TradingAgents/issues/750 ; 논문 "예측당 LLM 11회·툴 20+회"는 구 아키텍처 기준 [주장, 선행 노트].

**결정적 vs LLM** [확인]: 결정적 — 날짜 검증·`as_of` 클램프(`agents/tools.py`는 `trade_date`를 `InjectedState`로 주입해 모델이 날짜를 넘길 수 없음), 벤더 라우팅·폴백(`dataflows/router.py`), `get_verified_market_snapshot`(Yahoo 스냅샷 빌더 직접 호출), 종목 신원(`agents/context.py`: Yahoo `longName/shortName`·sector·industry·exchange·quoteType, `lru_cache(256)`, 실패 시 빈 dict로 fail-open), 토론 라우팅, rating 정규식, 메모리 선택(최근순), 정산 산식, 체크포인트 키. LLM — 분석가 4(+툴 선택), Bull/Bear, RM, Trader, Risk 3, PM, Reflector, 그리고 외부 분류기 Jev(`post_screen.py`, TypeSafe API).

**체크포인트·로그** [확인, `graph/trading_graph.py`, README]: opt-in(`checkpoint_enabled`/`--checkpoint`), `langgraph-checkpoint-sqlite`, 종목별 SQLite `~/.tradingagents/cache/checkpoints/`, thread 키 = 분석가 목록+토론/리스크 깊이+asset_type+포트폴리오 fingerprint+설정 해시(`results_dir, data_cache_dir, memory_log_path, checkpoint_enabled, llm_max_retries` 제외), 성공 시 자동 삭제. 전체 상태는 `results_dir/<safe_ticker>/TradingAgentsStrategy_logs/full_states_log_<trade_date>.json`에 `run_settings()`(엔드포인트·키·경로 제외 allowlist)와 함께 저장.

## 3. 데이터·메모리·설정

**벤더 라우팅** [확인, `dataflows/router.py`, `default_config.py`]: 카테고리 6개와 기본 벤더 — `core_stock_apis: "yfinance"`, `technical_indicators: "yfinance"`, `fundamental_data: "sec_edgar,yfinance"`, `news_data: "yfinance"`, `macro_data: "fred"`, `prediction_markets: "polymarket"`; `tool_vendors`(툴별 override, 기본 `{}`)가 우선. `VENDOR_METHODS`: `get_stock_data/get_indicators/get_fundamentals/get_news/get_insider_transactions` = alpha_vantage, yfinance; 재무제표 3종 = alpha_vantage, sec_edgar, yfinance; `get_global_news` = yfinance, alpha_vantage; `get_macro_indicators` = fred; `get_prediction_markets` = polymarket. 설정 문자열을 쉼표로 쪼갠 **목록이 곧 체인**(설정하지 않은 벤더로 조용히 넘어가지 않음; 이슈 #988/#989의 결과). 예외 분류: `VendorUnavailableError`→다음 벤더, `VendorNotConfiguredError`→다음, `NoMarketDataError`→"no data" 기록 후 다음, 기타→first_error. 최종: 불가용이 하나라도 있으면 `DATA_UNAVAILABLE` 문자열(종목 탓 안 함), 모두 no-data면 `NO_DATA_AVAILABLE` 문자열, 오류만 있으면 `OPTIONAL_CATEGORIES`(`macro_data, prediction_markets`)는 sentinel 반환·그 외는 재발생. **sentinel 문자열이 프롬프트로 흘러가고 하류에서 아무도 검사하지 않는다**는 것이 이슈 #1621의 요지. finnhub·Finnhub 키는 현재 트리에 없음; Alpha Vantage는 `ALPHA_VANTAGE_API_KEY` 필요, SEC EDGAR는 `SEC_EDGAR_USER_AGENT`, FRED는 `FRED_API_KEY`(옵션), Reddit은 RSS(429 이슈 다수), StockTwits, Polymarket, Jev는 `TYPESAFE_API_KEY`(README).

**캐시·온라인/오프라인** [확인, `dataflows/vendors/yahoo/ohlcv.py`, `yahoo/common.py`, `dataflows/files.py`]: 오프라인 모드나 `online_tools` 키는 없다(과거 버전의 키; 현재 `DEFAULT_CONFIG`에 부재). OHLCV는 종목당 1파일 `{safe_symbol}-YFin-data.csv`를 `data_cache_dir`(기본 `~/.tradingagents/cache`)에 저장, 다운로드는 오늘 기준 5년, Yahoo `end` 배타성 때문에 `end=내일`, look-ahead는 `Date <= as_of_dt` 필터로 별도 차단. `_cache_is_fresh`: 수정일이 **오늘**이 아니면 무조건 재수집; 과거 `as_of_date`면 당일 파일 재사용; 오늘 날짜면 `OHLCV_CACHE_TTL_SECONDS = 900`(장중 부분 캔들 대비, #1150) 이내만 재사용; 빈 파일·`Close` 없는 파일은 miss. `_assert_ohlcv_not_stale`: 최신 행이 `as_of_date`보다 `MAX_OHLCV_STALE_DAYS = 10`일 넘게 오래되면 `NoMarketDataError`(#1021). `yf_retry(func, max_retries=3, base_delay=2.0)` 지수 백오프(2/4/8초), `Ticker.history` 사용(`yf.download`은 rate-limit 예외를 삼키고 빈 프레임 반환), 초과 시 `VendorUnavailableError`; `_answered_empty`(404 또는 "Data doesn't exist")만 "데이터 없음"으로 분류. `replace_file`(uuid `.tmp` → `os.replace`), `locked(path, wait)`(fcntl/msvcrt). `net.py`는 캐시 없음, `get_scrubbed`(타임아웃 필수, API 키 `***` 마스킹, 재시도 없음), `vendor_reachable(timeout=5.0)`.

**Point-in-time** [확인, `dataflows/date_window.py`, `agents/tools.py`]: `as_of(requested, trade_date)`·`as_of_window(start, end, trade_date)`(창 전체가 미래면 길이 유지한 채 뒤로 이동), `in_window`(반개구간 `[start, end+1d)`, UTC), 날짜 없는 항목은 `end >= now-1d`일 때만 유지, `coverage_gap`은 빈 결과 대신 "unavailable" 안내, `withhold_live_profile/withhold_undisclosed_trades/withhold_undated_statements`는 과거 실행에서 현재 전용 데이터를 숨김. `get_insider_transactions`·`get_prediction_markets`는 로컬 클램프 없이 벤더에 위임. **소셜 피드는 아카이브가 없어 과거 실행의 감성 입력은 point-in-time이 아니다**(`sentiment_analyst.py` docstring, 창만 7일로 자름 #1220).

**메모리** [확인, `memory/log.py`]: 단일 markdown `~/.tradingagents/memory/trading_memory.md`(`memory_log_path`). 엔트리 = 태그 줄 + `DECISION:` + (정산 후) `REFLECTION:`; pending 태그 `[date | ticker | rating | pending]`, 정산 태그 `[date | ticker | rating | raw | alpha | Nd | resolved:YYYY-MM-DD]`; 구분자 `"\n\n<!-- ENTRY_END -->\n\n"`. `store_decision`은 파일락 아래에서 `[trade_date | ticker |`로 시작하는 줄이 있으면 **쓰지 않음**(재실행 중복 차단), LLM 호출 없음. `get_past_context(ticker, n_same=5, n_cross=3, as_of=None)`: **BM25·임베딩 없음**, settled만, 결정일 내림차순(동률은 쓰기 순), 같은 종목 5건 전문 + 타 종목 3건 reflection만(없으면 decision 앞 300자); `as_of`가 있으면 `resolved <= as_of`만(필드 없는 엔트리 제외, #1251). `memory_log_max_entries`(기본 `None`=회전 없음)는 resolved 블록만 오래된 순 삭제, pending은 절대 삭제 안 함. `update_with_outcome`은 `.tmp`→`replace`로 원자적, `settling()`은 별도 `.settle` 락.

**정산·reflection** [확인, `memory/settlement.py`, `memory/reflection.py`]: `settle_all_pending(memory_log, reflector, config, wait)`이 pending의 고유 종목마다 `settle_pending`; 그래프의 `"Memory Log"` 노드가 분석가와 병렬로 `wait=False` 호출(다른 패스가 락을 쥐면 건너뜀). `fetch_returns(ticker, trade_date, holding_days=5, benchmark)`: 진입 = `trade_date` **직후 첫 종가**(v0.7.0부터; 당일 종가 기준이던 구버전과 섞이면 혼합 채점 — CHANGELOG 0.7.0 upgrade note), 청산 = 진입 세션 +`holding_days` 거래일, raw = `(exit-entry)/entry`, 벤치마크는 같은 두 날짜의 `asof` 종가, alpha = raw − bench, `resolution_date` = 청산일; `_by_day`는 오늘 bar 제거·결측/0 이하 종가 제거; 창 종료 예정일이 지났는데 거래가 없으면 오늘+1일까지 재조회(장기 휴장, v0.7.1); 미완료면 `None` 4개. `resolve_benchmark`: `benchmark_ticker` → 접미사 맵(`.KS→^KS11`, `.KQ→^KQ11`, `.T→^N225` 등 20개) → `""→SPY`. 실패 시 pending 유지(가격 "prices unavailable"/"reflection failed"로 `Settlement.failed`에 기록), 실행은 계속. `Reflector(quick_llm).reflect_on_final_decision(final_decision, raw_return, alpha_return, benchmark_name="SPY", holding_days=5)`: "exactly 2-4 sentences of plain prose", (1) 창의 alpha 수치 인용·창이 짧으면 판단 불가 명시 (2) 테제의 어느 부분이 지지/반박 (3) 다음 분석에 적용할 구체 교훈 1개; 재시도·형식 검증 없음(예외는 호출자에게 전파).

**설정 노브** [확인, `default_config.py`]: `max_debate_rounds=1`, `max_risk_discuss_rounds=1`, `max_tool_rounds=20`, `max_recur_limit=100`, `news_article_limit=20`, `global_news_article_limit=10`, `global_news_lookback_days=7`, `global_news_queries`(5개 매크로 질의), `holding_period_days=5`, `benchmark_ticker=None`, `benchmark_map`, `checkpoint_enabled=False`, `output_language="English"`, `temperature=None`, `llm_max_retries=None`, `max_tokens=None`, `google_thinking_level/openai_reasoning_effort/anthropic_effort=None`, `memory_log_max_entries=None`, `results_dir`(`~/.tradingagents/logs`). 환경변수 `TRADINGAGENTS_*` 20개 매핑. `_coerce`는 기존 기본값의 타입으로 변환하며 bool(`true/1/yes/on`, `false/0/no/off` 외 `ValueError`)/int/float 실패 시 `Invalid value for <ENV_VAR>`로 **시작 시 실패**. 단, 기본값이 `None`인 키(`temperature, llm_max_retries, max_tokens, memory_log_max_entries, benchmark_ticker`)는 타입 정보가 없어 원문 문자열이 그대로 들어간다(다른 곳에서 변환하지 않으면 `"3"`이 문자열로 남음) — 이식 시 모든 키에 타입 있는 기본값을 두는 것이 안전. 설정 스코프는 `dataflows/config.py`: 프로세스 전역 `_config` + run별 `ContextVar _run_config`(`run_config()` 컨텍스트매니저, LangGraph가 툴 호출까지 컨텍스트를 전달), `get_config()`는 항상 deep copy 반환, 전역 변경에는 락 없음.

## 4. 평가와 한계

**backtest 설계** [확인, `tradingagents/backtest.py`, `cli/main.py`]: docstring — "decision-quality evaluator", 포트폴리오 시뮬레이터가 아니며 그렇게 커지면 안 됨(수량·체결가·현금 원장 없음), 셀 독립, 포트폴리오를 주면 모든 셀에 같은 standing book. `iter_grid(start, end, every_n_days=1)`(오늘까지로 cap), `run_backtest(tickers, dates, config, asset_type="stock", portfolio=None, selected_analysts=(4종), run_id=None, progress=None) -> BacktestResult(run_id, log_path, cells_run, skipped, failures[(ticker,date,error)], settlement_failures)`, `summarize(result|path) -> BacktestSummary(resolved, pending, by_rating{rating: RatingScore(count, hit_rate|None, mean_alpha)}, unscored, holding)`. 방향 규칙: Buy/Overweight=+, Underweight/Sell=−, Hold=방향 없음(`hit_rate=None`); `REVIEW`는 `unscored`; alpha 미파싱은 pending으로 집계. 로그는 `<results_dir>/backtest/<run_id>/trading_memory.md`(라이브 로그 분리), 같은 `run_id`면 `(ticker, date)` 완료 셀 skip, `run_id`는 `safe_ticker_component`로 검증. 종목당 정산은 모든 셀 실행 후 1회. alpha는 로그에 소수 1자리 %로 저장돼 집계 정밀도 ≈0.1%p. **거래비용·슬리피지·수량 없음, 동시성 없음, 유의성 검정 없음.** CLI: `tradingagents backtest <tickers> --start --end [--every 7] [--analysts] [--asset-type stock|crypto] [--portfolio] [--run-id]`; `tradingagents`(=analyze 콜백) `--ticker --date --analysts --save/--no-save --show/--no-show --html/--no-html --checkpoint/--no-checkpoint --clear-checkpoints --portfolio`; `login/logout`(chatgpt 프로바이더). settle 전용 명령은 없고 Python `ta.settle_all_pending()`만(README).

**구조적 한계(코드에서 직접 읽히는 것)** [확인]: (a) 결정은 rating 1개이지 주문이 아님(수량·체결 없음; `portfolio.py`는 입력 스냅샷일 뿐), (b) 감성 입력은 PIT 불가, (c) Bull/Bear·Risk 노드는 자유 텍스트 f-string 프롬프트와 `llm.invoke`로 구조화 출력이 없어 토론 내용의 기계 검증이 불가, (d) reflection은 형식 검증·재시도 없음, (e) 라우터 sentinel 문자열이 프롬프트로 흘러감, (f) 백테스트 셀마다 전체 멀티에이전트 실행 + 정산 시 reflection LLM 호출이 붙어 표본을 키우기 비쌈(#1630 작성자도 지적).

## 5. 이 프로젝트에 옮길 것 / 옮기지 말 것

전제(프로젝트 하드 룰): LLM은 라이브 주문 경로에 들어가지 않는다. 따라서 TradingAgents의 "그래프"는 통째로 비적용이고, 가치는 주변부(원장·정산·평가·fail-loud·분류 규약)에 있다. 선행 노트의 결론을 이번 확인 결과로 구체화했다.

| 구성요소 (파일) | 판정 | 이유·이식 형태 |
|---|---|---|
| append-only 결정 로그 + idempotency guard (`memory/log.py`: `[date \| ticker \| rating \| pending]` 태그, `store_decision`의 prefix 검사, pending 절대 미삭제, `.tmp`→`replace`) | **옮김** (SQLite 스크립트) | 기존 SQLite 원장에 `decisions` 테이블: `UNIQUE(trade_date, arm, ticker)`, `status ∈ {pending, settled, review}`, settled 전이는 UPDATE만 허용·DELETE 금지, 야간 잡 재실행 시 중복 INSERT 무시. 파일락 대신 SQLite 트랜잭션. 규칙 봇은 LLM 결정이 아니라 **arm의 시그널 발생 사실**을 기록 |
| 벤치마크 대비 정산 (`memory/settlement.py`: 첫 종가 진입, N거래일 청산, 같은 날짜 `asof` 벤치마크, 오늘 bar 제외, 휴장 재조회, 실패 시 pending 유지) | **옮김** (야간 스크립트) | 차이점 2개를 명시해 이식: (1) 규칙 봇은 **실제 체결가**가 있으므로 진입/청산은 체결 기록을 쓰고 "첫 종가" 규칙은 미체결 시그널(counterfactual) 전용으로 분리, (2) 벤치마크는 arm별로 `^KS11`/`^KQ11`(TradingAgents 접미사 맵과 동일 심볼) 또는 동일 유니버스 등가중, `holding_days`는 arm별 보유기간. "오늘 bar 제외"·"장 마감 전 정산 금지"는 그대로 |
| reflection 프롬프트 (`memory/reflection.py`: 2~4문장, alpha 수치 인용, 창이 짧으면 판단 불가 명시, 교훈 1개, verbatim 저장) | **옮김** (야간 LLM 스킬) | 단위를 **거래가 아니라 arm×주간 통계**로 바꾼다: 입력 = arm의 주간 trades/hit/mean alpha/MDD/regime, 출력 = 2~4문장 + "교훈 1개"; `review_notes` 테이블에 verbatim 저장하고 **라이브 파라미터에는 자동 반영 금지**(사람이 다음 주 사전등록에 반영). TradingAgents처럼 형식 검증이 없으면 안 되므로 문장 수·수치 포함 여부를 코드로 검사, 실패 시 `REVIEW` |
| REVIEW rating (`agents/rating.py`: 파싱 실패 = 거래 불가 sentinel, Hold로 기본값 금지; `backtest.summarize`는 REVIEW를 `unscored`로 분리 집계) | **옮김** | 야간 채널 분류기 출력 스키마에 `REVIEW` 라벨 추가: 구조화 출력 실패→평문 1회 재시도→정규식 파싱→실패 시 `REVIEW`(`neutral/unknown`과 구분). 집계 시 `unscored` 건수를 항상 보고. "읽을 수 없는 결정은 Hold가 아니다"(#1170)를 분류기 품질 지표로 사용 |
| post_screen 2질문 분류기 (`agents/post_screen.py`: Q1 관련성 확률(`_OFF_TOPIC_BELOW=0.3`), Q2 방향 choice+신뢰도(`_STANCE_CONFIDENCE=0.5`, 미달은 `unclear`), 16 workers, 429/529 `Retry-After`≤30s·지터 백오프·3회, 실패 시 **미스크리닝 상태로 보존 + 블록에 명시**) | **옮김** (구조만; Jev/TypeSafe는 비적용) | Telegram 채널 메시지 분류를 같은 2단계로: Q1 "특정 종목/시장 이벤트에 관한 글인가"(확률), Q2 "방향(bullish/bearish/neutral)+confidence"; 임계값은 gold-label 표본으로 재추정. 분류기 호출 실패 시 메시지를 버리지 않고 `screened=false`로 저장. 외부 분류 API(Jev)는 영어 소셜 포스트용·추가 키 필요라 비적용, 자체 LLM 호출로 대체 |
| fail-loud 설정 (`default_config.py` `_coerce`: 잘못된 환경변수는 시작 시 `ValueError`) | **옮김** | 봇 설정 로더에 동일 규칙. 단, 확인된 결함(기본값 `None`인 키는 타입 없음→문자열 통과)을 피하려 모든 키에 타입 있는 기본값 또는 명시 타입 테이블을 둔다. 모의/실전 키·주문 허용 플래그는 특히 bool 엄격 파싱 |
| backtest 격자 = 결정 품질 평가기 (`backtest.py`: 셀 독립, rating별 `count/hit_rate/mean_alpha`, `unscored`/`pending` 분리, `run_id` 재개, 라이브 로그와 분리) + #1630 permutation test | **옮김** (분류기 평가용) / **참고만** (arm 평가용) | 13개 arm은 이미 실제 체결 원장이 있으므로 격자 재실행은 불필요. 대신 **야간 분류기 라벨**을 셀로 보고 "라벨(bullish/bearish)이 익일~N일 alpha 방향을 맞혔나"를 `by_label` 표로 집계하고, #1630 방식(같은 날짜 내 종목 간 라벨 셔플, p값)으로 우연 대비 검정 — LLM 추가 호출 없이 SQL+표준 라이브러리로 가능. arm 평가에는 선행 노트의 DSR/Harvey-Liu haircut이 우선 |
| 토론 구조 (`researchers/`, `risk_mgmt/`, `conditional_logic.py`: Bull→Bear→RM, 라운드 수 `count >= 2*rounds`) | **참고만** | 야간 "arm별 주간 bull/bear 리뷰"로만: 입력은 arm의 주간 통계(거래당 아님), Bull/Bear 각 1턴 고정(라운드 증가는 비용·history 선형 증가만 낳음, #750), 판정은 RM 프롬프트가 아니라 **사전등록된 kill-rule 수치**로. RM/PM의 "conflict alone is not a reason to Hold"는 라이브 봇에 반대로 적용해야 함(불확실하면 **변경하지 않음**이 기본) |
| 리스크 페르소나 3인 + PM (`aggressive/conservative/neutral_debator.py`, `portfolio_manager.py`) | **참고만** → 사전등록 kill-rule 체크리스트 | 페르소나를 고정 질문 목록으로 치환: Aggressive="최소 거래 수 도달 전 조기 kill 아닌가/표본 부족", Conservative="MDD·노출·연속 손실 한도 초과", Neutral="regime 변화로 통계가 오염됐나". 답은 SQLite 수치에서 결정적으로 산출하고 LLM은 야간 요약문만 작성. 라이브 리스크 판단에 LLM 금지 |
| LangGraph 그래프·Trader 노드(`graph/*`, `trader/trader.py`: Buy/Hold/Sell + 절대 가격 entry/stop) | **비적용** | 주문 경로에 LLM 금지. `TraderProposal`의 "entry/stop을 절대 가격으로" 규약만 arm 사전등록 템플릿 필드명으로 차용 |
| 분석가 툴 루프(`max_tool_rounds=20`, `WRAP_UP` 강제 종료) | **비적용** | 비용·비결정성. 단 `get_verified_market_snapshot`의 "결정적 스냅샷이 단일 진실, 충돌 시 숫자를 합치지 말고 불일치 표기" 규약은 **야간 리서치 리포트 규칙**으로 옮김: 리포트의 모든 수치는 SQLite/pykrx 조회 결과를 인용해야 하며 LLM이 산출한 숫자는 "unverified"로 표기 |
| point-in-time 도구(`dataflows/date_window.py`: `as_of`, `as_of_window`, `in_window`, `coverage_gap`, `withhold_*`; 툴에 `trade_date`를 `InjectedState`로 주입) | **옮김** (야간 리서치 데이터 규칙) | 야간 리서치·분류 입력에 `as_of` 클램프 함수 1개 + "미관측 창은 빈 결과가 아니라 unavailable 안내" 규칙 + 날짜 없는 항목은 과거 모드에서 제외. 선행 노트의 `published_at/ingested_at/is_correction` 3필드와 결합. | 체크포인트/재개(`graph/checkpointer.py`, `backtest run_id` 재개, 설정 해시 포함 thread 키) | **옮김** (단순화) | 야간 잡을 `(run_date, step)` 단위 idempotent로: 완료 단계 skip, **설정 해시가 바뀌면 재개 금지**(포트폴리오 fingerprint 아이디어) |
