# 모의 gdcrs/B3 미체결 매수 만료 옵션

## 현재 공통 계약 (2026-11-03)

현재 자동 모의 지정가 매수 TTL은 gdcrs/B3뿐 아니라 S2~S5, 모의 실험 arm,
정확한 `rsv#<양수>` 예약 전략을 확인한다. 수동·미확인 주문은 제외한다.
모의 실험 프로필의 기본 TTL은 180초이며, D·VSS·LDR은 원 주문 판단 해시에
연결된 유효 종가 단일가 주문 창의 종료(15:30)를 만료로 사용한다. 창 근거가
없거나 무효이면 180초를 유지한다. C·GDR은 기존의 180초와 유효 창 종료 중
이른 시각을 사용한다. 한 주기의 만료 주문 전부를 순차 확인하고 매 주문마다
신선한 원장·완전한 미체결·00/세션 상태와 전송 직전 가드를 다시 검사한다.
조회·취소는 공용 큐의 요청 간격을 지키며, 배치 소요 시간은 상태에 남긴다.

최종 취소는 아래의 ACK·연결된 취소 자식·고유 00·완전 REST·게시 검증을 모두
통과해야 예약에서 해제된다. 실제 kt00009의 원주문 `일반`, 취소 자식 `취소`,
00의 바깥 ASCII 공백만 명시적으로 정규화하며 번호·수량·가격 검사를 유지한다.
읽기 전용 정비 후보 검증은 정산 완료나 예약금 해제를 뜻하지 않는다.
미해결 정산 로그는 주문 번호 순환과 관계없이 로컬 수신기에 10분마다 한 줄이다.
모의 실험의 예산·한도 계약은 `docs/PAPER_EXPERIMENT.md`를 따른다.

아래의 옵션 기본 0, gdcrs 전용 범위, 100만 원 한도 설명은 최초 레거시 옵션의
계약이다. 위 공통 TTL 및 현재 모의 실험 프로필과 구분한다.

`gdcrs_unfilled_buy_ttl_seconds`의 기본값은 `0`(비활성)이다. 기존 파일에
키가 없을 때도 메모리에서 0으로 해석하며, 읽기만으로 설정 파일을 고치지
않는다. 실전 모드에는 항상 0을 적용한다. 이 문서는 소스·격리 테스트 준비
상태를 설명하며 운영 활성화나 실제 취소 주문 실행을 뜻하지 않는다.

양수(예: 180초)를 선택하면 기존 수신기의 직렬 gdcrs 루프가 정규장 내에서
최대 30초 간격으로 만료 대상을 살핀다. 시간은 사전 intent 생성 시점이
아닌, 원장에 주문 접수 응답을 기록한 `orders.registered_at`부터 센다.
조회/큐 지연이나 상태 확인 실패가 있으면 취소 시각을 보장하지 않는다.
별도 작업자, 로그인, WebSocket, 연구 IPC 폴링은 만들지 않는다.

대상은 현재 거래일·현재 원장 계좌 범위의 `gdcrs` 전략이 접수 완료한
KRX 지정가 매수뿐이다. B3 최초/추가 매수는 이 전략 ID를 사용한다.
S2~S4·OF·수동·다른 계좌/날짜·시장가·매도·접수 미확정 주문은 제외한다.
기존 자동매매가 정지되어 있거나 정규장 밖이면 이 옵션도 주문을 보내지 않는다.

취소 조건은 다음을 모두 확인한다.

- 원주문과 일치하는 accepted intent·불변 가격 결정·종목·수량·전략 기록.
- 공유 큐로 새로 조회한 통합 `ka10075`에서 원주문 번호, KRX, 매수,
  종목, 지정가, 원수량, 실제 미체결 잔량, 같은 날 주문 시각이 모두 일치.
- 부분체결 후 잔량과 원장의 체결 수량 합이 원주문 수량과 일치.
- 세션·00 수신기 객체·수신/콜백 카운터·체결 원장 워터마크가 조회 전후 및
  실제 전송 직전 동일하고, 처리 대기 콜백이 없음.
- wall clock와 monotonic clock 모두 조회 시작 이후 10초 이내이고 날짜,
  설정, 전략 활성, 유지보수 및 외장 저장소 가드가 유지됨.

취소 시도는 `.execution-ledger.sqlite3`의 불변
`buy_ttl_cancellation_attempts`에 먼저 커밋한다. 원주문별 1회 claim으로
동시 실행, 응답 유실, 프로세스 재시작에도 자동 재전송을 막는다. 결과는
별도 불변 `buy_ttl_cancellation_outcomes`에 원주문과 취소주문 번호를 연결한다.
장부 확장은 옵션을 켜고 실제 시도가 있을 때만 생성한다.

`kt10003` 요청은 명세상 잔여 전량을 뜻하는 `cncl_qty="0"`을 사용한다.
전송 직전 알려진 체결 변화는 가드에서 차단하고, 마지막 검사 이후 발생한
부분체결 경합은 증권사가 해당 원주문의 남은 잔량에만 취소를 적용하도록
한다. 매도 주문, 보유 주식 청산, 재매수로 대체하지 않는다. 취소 요청은
기존 `queued_open`을 사용하며 재시도하지 않는다.

**취소 입력 접수와 최종 취소 확정은 다르다.** ACK는
`cancel_input_ack_unconfirmed_settlement`로 기록하며 그 자체로 예약을
해제하지 않는다. 다음 직렬 확인 주기에서 다음 증거를 **모두** 요구한다.

- 자신이 기록한 취소 ACK의 자식 주문 번호와 원주문 번호가 일치하고,
  후속 `00`에서 현금·KRX·매수취소·거부사유 없음·확인/취소 상태가 관측됨.
  취소 자식의 체결 ID·누적/단위 수량·체결금액/가격이 상충하면 보류함.
- 새 `ka10075` 통합 전체 조회가 마지막 페이지까지 완료되어 원주문 및
  정정/취소 체인의 잔량이 없고, 새 `kt00009(qry_tp=0)` 전체 주문 조회에서
  원주문과 취소 자식의 확인 수량·종목·계좌 범위·거래소가 일치함.
- 실제 매수 체결은 고유 `00` 단위체결 ID·수량·대금의 누적 연속성으로
  확인하고, 원장 projection 및 `kt00009`와 대사함. REST 평균 체결 행을
  단위체결에 합산하지 않음. 정수 평균의 원 단위 절사는
  `0 <= 실제 00 약정금액 - 평균가 × 수량 < 수량` 범위만 허용하며 실제
  매입원금은 `00` 단위체결 대금을 사용함. 평균가 올림/다른 규칙은 보류함.
- 전체 원주문→정정/취소 체인에 미확인 자식이 없고, 같은 현재 모의 세션에
  정확히 연결된 계좌 tracker/수신기·콜백 카운터가 확인 시작부터 커밋까지
  유지됨. wall clock와 monotonic clock 모두 20초 이내이며 늦은 체결이나
  원장 변경이 발생하면 확정을 보류함.

부분체결 3주/원주문 10주 예에서는 3주의 실제 매입원금과 보유를 남기고
취소 확인된 7주에 해당하는 미체결 예약만 종료한다. 전량체결 경합은
`fill_resolved`, 취소 수량 0으로 기록하며 취소 성공으로 표시하지 않는다.
원주문 수량·접수된 매수 횟수·intent·체결·보유·현금 행과 기존 금융 CSV를
수정하지 않는다. 취소된 주문도 일일 매수 접수 상한에는 계속 포함된다.
현금을 로컬에서 가산하지 않으며 다음 주문은 새 계좌/미체결 관측,
zero-position v5 또는 보유 대사, 전 전략 합산 100만 원 한도를 다시 통과한다.

최종 증거는 불변 `buy_ttl_cancellation_settlements`에 추가한다. 그 뒤
동기적으로 회계 sidecar의 별도 `cancellation_settlements` 주석을 원자적
게시하고, 게시 해시를 `buy_ttl_cancellation_publications`에 기록한 다음에만
예약 gate가 해제된다. 게시 실패 시 증거가 있어도 예약은 유지한다. 재시작은
새 현재 세션의 전체 조회로 확인/게시를 다시 할 수 있으나 취소 주문을
재전송하지 않는다. 게시 표식은 최초 게시 시점의 해시 증거이며 매 주문마다
현재 파일 해시를 다시 확인하는 파일 감시 기능은 아니다.

이후 같은 원주문/자식의 새 체결·REST 정정이 기존 증거와 달라지면 해당
해제 증거는 무효화되고 새 주문은 보류된다. 다른 종목의 새 정상 주문이나
동일한 중복 수신, REST 페이지 분할 차이는 기존 확정을 무효화하지 않는다.
정산이 끝난 뒤 후속 tick/재시작 상태가 다시 미정산으로 돌아가지 않는다.

종료 확인을 기다리는 정상 미확정은 기존 30초 확인 주기를 사용한다.
세션/스키마/계정/파일 오류 및 불확실 취소 응답은 `manual_review_required`로
멈추며 취소를 자동 재전송하거나 확인 주기를 단축하지 않는다. 단순히
`ka10075`에서 주문이 사라졌다는 이유로 취소 완료를 추정하지 않는다.
이 보수적 계약을 실제 브로커의 부분취소 응답으로 실증한 상태는 아니며,
필수 필드·완료 증거가 부족하면 `unconfirmed` 또는 수동 검토를 유지한다.
