# 원장 저장·보관 계획 — 승인 전 실행 금지

SQLite `.execution-ledger.sqlite3`의 불변 관측 및 경제행이 원본이다. 일별 JSONL은
원장을 내보낸 파생 감사 사본이며, JSONL을 옮겨도 원장 행·고유 00 체결·비용·소유 이력은 지우지 않는다.
이번 소스 보완은 기존 SQLite의 저널 모드를 변경하거나 운영 JSONL을 이동하지 않는다.

## 중복 REST 관측

같은 세션·scope·모드·요청·API·페이지·연속조회 조건의 성공 응답 본문이 직전 본문과
같을 때만 원본을 참조하는 작은 불변 repeat 영수증을 추가한다. 새 query ID, 요청/응답 시각,
페이지 완전성, 본문 해시와 완성 이벤트 해시를 모두 보존한다. 00 체결은 중복 압축 대상이 아니다.
원본·repeat·전역 관측 ID는 함께 읽는다. 새 읽기 어댑터는 실제 URI `mode=ro` 연결에 TEMP 뷰를
설치한 뒤 `query_only=ON` 및 하나의 읽기 트랜잭션에서 해시를 검증한다. `trusted_schema=OFF`는
유지한다. 독자가 repeat를 지원하지 않으면 최신 증거라고 추정하지 않는다.

운영에 적용하기 전 수신기뿐 아니라 장후 보고 및 일지의 repeat 지원 버전도 확인한다.
새 스키마를 만든 뒤 구 버전 수신기를 단순 실행하는 롤백은 허용하지 않는다. 구 버전은 압축된
최신 관측을 빠뜨릴 수 있으므로, 새 스키마를 읽는 검증된 호환 버전으로만 복구한다.

## WAL 별도 마이그레이션 제안

1. 별도 사용자 승인과 장후 공식 종료 증거를 확보한다. 신규 주문을 막고 미해결 주문·보유 청산
   연속성을 확인한다. 원장 생산자/독자 목록과 정확한 배포 버전을 기록한다.
2. SQLite backup API로 일관된 스냅샷을 로컬 및 마운트 가드가 확인한 SSD에 저장한다.
   `quick_check`, 원본/백업 schema, 경제행·00·repeat 해시와 파일 readback 해시를 대조한다.
   열린 DB를 단순 파일 복사하지 않는다.
3. 실제 크기의 격리 사본에서 WAL 전환, 수신기 쓰기와 복수 RO 독자의 동시 읽기,
   장시간 독자·checkpoint 지연·프로세스 강제 종료·재기동 복구·디스크 부족을 시험한다.
   `-wal`/`-shm` 수명과 backup/checkpoint의 일관성, 수수료/체결 집계 동일성을 검증한다.
4. 승인된 운영 창에서만 전환한다. 페이지 크기/저널 모드/동기화 정책을 근거로 기록하고,
   지속되는 lock 대기·WAL 증가·독자 stale 상태에 대한 중단 기준을 먼저 정한다.
5. 복구는 모든 DB 핸들을 닫은 상태에서 일관된 스냅샷으로만 수행한다. 스냅샷 이후 새 주문/
   체결이 존재하면 과거 DB로 덮지 않는다. 먼저 후속 행 대사와 복구 계획을 별도 승인받는다.

## 7거래일 경과 JSONL 보관 설계

- 공식 거래일 목록으로 7개 실제 정규 세션이 지났는지 확인한다. 단순 달력 7일로 대체하지 않는다.
- 해당 일자의 미해결 주문·취소·비용 또는 아직 기록 중인 파일이 있으면 보관 후보에서 제외한다.
- 파생 파일의 원본 경로, 거래일, API, 바이트 수, 줄 수, SHA-256, SQLite 관측 ID 범위,
  원본·repeat 각 행 수, 생성/확인 시각을 manifest로 고정한다.
- 승인 후 마운트 가드/FD 고정 쓰기로
  `/Volumes/AIStockData/ai-stock-research-data/broker-jsonl-archive/<거래일>/<작업ID>/`
  아래에 충돌 없이 복사한다. 원본과 목적지 전체 readback 해시가 같고 새 행이 추가되지 않았음을
  확인한 뒤에만 로컬 파생 사본을 제거한다. 중단 시 원본을 남기고 동일 작업을 자동 재시도하지 않는다.
- 전환 전후 JSONL 독자 경로를 manifest로 연결하고, SQLite 원장 및 audit trigger는 변경하지 않는다.
  복구는 manifest가 검증한 파생 파일 복사이며 운영 SQLite 덮어쓰기가 아니다.

## 성능 측정의 구분

운영 전 1시간의 실제 추가 행 수와 격리 동일 시계/동일 응답 시나리오의 전후 결과를 따로 표시한다.
원본 raw 행, repeat 영수증 행, 합계, 바이트, API 요청 수를 각각 센다. 압축 자체는 관측 횟수나
API 호출 수를 줄이지 않으며, 완료일 재조회 스케줄 완화 효과와 중복 본문 압축 효과를 섞지 않는다.
운영 후 시간당 증가량은 별도 배포 승인과 실제 1시간 관측 이후에만 확정한다.
