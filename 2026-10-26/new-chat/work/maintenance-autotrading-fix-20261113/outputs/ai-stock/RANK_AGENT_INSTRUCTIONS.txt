2. 사용자 동작

  2. 상승률 상위 20종목
  3. 거래량 상위 20종목
  4. 인기검색 상위 20종목
  사용법: rank 1 / rank 2 / rank 3 / rank 4

- 추가 문법은 rank {1~4} cmd {1~20} {종목 명령}입니다. 예: rank 4 cmd 15 gdcrs add ( ) 100000. 한 번 조회한 순서대로 지정 개수의 종목코드를 템플릿의 단 한 개 ( ) 또는 () 위치에 넣어 실행하세요. 지원 대상은 기존 srch, buy, sell, gdcrs add이며, 다른 전체 설정·로그인·재귀 rank 명령을 임의로 실행하지 마세요. 시장·기간·거래소를 명령 인자로 추가하는 확장은 필요하지 않습니다.
- 일괄 실행은 조회 결과 전체와 각 명령의 문법을 먼저 검증하고, 같은 종목코드를 중복 실행하지 마세요. 원래 명령 핸들러를 재사용하고 새 주문 전송 경로를 만들지 마세요. 로그인 변경·중지 요청·불확실한 주문 결과는 후속 명령 중단에 반영하고 완료된 명령을 자동 재실행하지 마세요.

3. 조회 의미와 기본 범위

- rank 1은 ka10032의 거래대금 순위, rank 2는 ka10027의 상승률 정렬, rank 3은 ka10030의 거래량 정렬을 사용하세요. 상승폭, 하락률, 거래회전율을 해당 순위로 잘못 사용하지 마세요.

- ka00198의 조회 구간은 초기 제품 선택으로 1분을 사용하고 결과 제목에도 '1분 기준'을 명시하세요. 이것이 API의 생략 가능한 기본값이라는 뜻은 아닙니다. 문서상 구분은 필수입니다. ka00198에는 시장·거래소 선택 필드가 없으므로 rank 1~3의 요청 필드를 얹거나 '코스피·코스닥 전체/통합거래소'라고 결과 범위를 단정하지 마세요.

5. API 호출과 상위 20개 확보

- 명세에 따른 POST, 고정된 운영/모의 도메인, TR별 URL, API ID와 Bearer 헤더를 사용하세요. 세 TR의 순위정보 경로와 ka00198의 종목정보 경로가 다릅니다.

- 모든 HTTP 요청은 utils/http_queue.py의 queued_open을 사용하고 공통 전송 제한·대기열·동일 대기 요청 병합을 거치게 하세요. 대기열의 초당 5회 미만 정책을 우회하는 opener.open 직접 호출을 추가하지 마세요. 응답 크기 제한을 max_bytes로 전달하고, 대기 후 전송 직전에도 현재 로그인과 토큰 사용 가능 여부를 before_send로 재확인하세요. 시간·대기·전송은 테스트에서 대체하세요.
- 최초 요청에는 이전 조회의 연속조회 정보를 사용하지 마세요. 20개가 아직 모이지 않았고 응답 헤더 cont-yn이 Y이면 응답의 next-key를 그대로 다음 요청 헤더에 전달하세요. 요청 본문의 조회 조건은 페이지 사이에 유지하세요. 헤더 이름의 대소문자를 구분하지 마세요.
- 20개가 확보되면 추가 요청 없이 중단하세요. 응답이 더 많으면 앞의 20개만 사용하세요. 서버가 정상적으로 종료했는데 20개보다 적으면 실제 제공 건수를 표시하고 제공된 결과를 보여 주세요. 빈 목록이면 '조회 결과가 없습니다'라고 반환하세요.

- API가 제공한 행 순서를 보존하세요. 표시용으로 반올림한 값이나 문자열 숫자로 다시 정렬하지 마세요. 같은 응답 종목 코드가 페이지에 반복되면 최초 행을 유지하고 중복이 20종목 수를 채우지 않게 하세요. 거래소 접미사를 근거 없이 제거해 서로 다른 코드를 합치지 마세요.

6. 텔레그램 출력

- 제목에 순위 종류, 모의/실전 구분, 실제 요청 범위 또는 조회 구간, 조회 완료 시각(KST)을 넣으세요. 이는 조회 시각이며 모든 행이 동일 시점의 실시간 데이터라는 보장은 아닙니다. ka00198의 제공 기준 일시가 있으면 조회 시각과 구분해 보여 주세요.
- 각 행에는 표시 번호, 종목명, 종목코드와 해당 순위의 핵심 값이 있어야 합니다. 거래대금은 거래대금, 상승률은 부호가 있는 등락률, 거래량은 거래량을 표시하세요. 인기검색은 제공 순위와 제공된 순위 변동을 사용하고 조회 횟수를 만들어 넣지 마세요.
- 금액과 수량은 문서에 적힌 원 단위를 확인하세요. ka10032의 거래대금은 백만원이며 억원 표시에는 Decimal로 100으로 나눕니다. ka10030 거래량은 1주, ka10027 등락률은 이미 백분율로 제공되므로 다시 100을 곱하지 않습니다. 단위를 제목이나 각 값에 분명히 표시하세요.
- 현재가를 추가 표시한다면 문서의 부호가 가격 변동 표현이라는 점을 처리하고 음수 현금 가격으로 표시하지 마세요. 선택 필드를 불필요하게 추가 API 호출로 채우지 마세요.
- 일반 텍스트 메시지 목록 list[str]을 반환해 listener의 기존 _send_replies 흐름을 사용하세요. telegram/commands/report.py의 _chunks와 같은 방식으로 한 메시지의 길이를 여유 있게 제한하고, 한글·이모지의 UTF-16 길이를 고려하세요. 종목 행이 가능한 한 같은 메시지에 있게 하세요.
- 전송 결과가 불확실하면 기존 동작대로 후속 조각을 중단하고 자동 재전송하지 마세요. 분할 때문에 키움 조회나 명령 실행을 반복하지 마세요.
