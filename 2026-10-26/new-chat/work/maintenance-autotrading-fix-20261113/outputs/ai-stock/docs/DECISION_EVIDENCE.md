# 주문 당시 판단 근거

`automated_orders`의 선택적 evidence와 `order_decision`은 당시 값을 불변 JSON으로 고정한다.
자동주문을 전송하기 전 `ExecutionTracker.prepare_order`가 주문 의도와 `order_decisions`를
하나의 SQLite 트랜잭션에 저장한다. 기록 실패·불일치면 HTTP 전송을 하지 않는다.

- `order_price`, `order_type`: 실제 주문 인자의 지정가/시장가. 전달되지 않은 과거 호출은 unknown.
- `evidence_json`, `evidence_sha256`: allowlist·최대32KiB 검증을 통과한 당시 근거.
- 완료 1분봉 창의 시각·종가, 단/장기 기간, 이전/현재 차이, 설정과 예산, 관측/평가시각.
- `source_kind`: 실제 기본 조회는 broker_observation, 주입된 조회는 기본 unknown. 테스트가 명시하면 synthetic.
- `run_id`는 모니터 인스턴스 범위이며 로그인/계좌 전체의 run 증거가 아니다.
- 전략 SHA는 모니터 모듈, 자료 SHA는 정규화 완료봉 창에 대한 값이다. 프로그램 전체·원시 응답을 인증하는 해시는 아니다.

이 기록은 신호가 생겨 주문 경로로 진입할 때만 생성한다. 전수 후보/평가 아카이브가 아니며
이 행수로 전체 평가수·전략 적중률을 계산하면 안 된다. 근거 생성이 주문 여부를 바꾸거나
이미 사용한 봉을 재생하지 않는다. 당시 값이 없는 과거 의도는 그대로 미확인이다.

`profit_observations`는 당일 종목별 비용 조회의 검증된 가격·매입단가·수량·수수료·세금과
귀속 상태를 덮어쓰지 않고 보존한다. 같은 값은 digest로 중복 저장을 막는다. 원시 계좌 응답·
토큰은 저장하지 않는다. 파싱 실패·범위 불일치의 순손익을0으로 채우지 않는다.

의도/판단근거 및 비용 관측에는 변경·삭제 금지 트리거가 있다. 이는 앱 수준 불변성 장치이며
DB 파일 소유자의 모든 변경을 방지하는 암호학적 서명은 아니다. 이번 변경으로 과거 계좌 성과나
현재 실시간 가동 여부가 검증되는 것은 아니다.
