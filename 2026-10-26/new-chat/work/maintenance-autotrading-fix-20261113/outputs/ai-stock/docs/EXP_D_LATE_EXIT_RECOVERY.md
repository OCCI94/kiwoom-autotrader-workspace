# EXP_D 개장 청산과 지연 청산

이 문서는 2026-11-05 사용자 요청에 따른 **소스 계약**이다. 운영 배포, 실제 주문,
현재 보유 청산 완료의 증거가 아니다. 모의 실험의 기존 설정·한도·배정은 변경하지 않는다.

## 현재 시각의 청산으로 처리

- 원래 EXP_D 배정, 매수 의도에서 시작한 소유세대, 고유 00 최초 체결을 연결한다.
  다른 전략의 보유나 단순 계좌 잔고를 EXP_D 소유로 가져오지 않는다.
- 검증된 공식 세션의 실제 개장부터 첫 1분은 정상 개장 청산이다. 이를 놓친 보유는
  같은 공식 정규장 안에서 `late_recovery_exit`로 평가한다. 휴장, 장전, 세션 종료 뒤,
  달력 미검증 상태나 같은 날 새로 매수한 EXP_D에는 이 예외를 적용하지 않는다.
- 지연 청산의 신호·관측·전송 시각은 실제 현재 시각이다. 09:00 신호나 시초가 체결로
  소급하지 않는다. 기존 주문·배정·체결·수신 공백·손익 원문은 보존한다.
- 오늘 관측한 공식 개장 시각과 원래 계획한 익일 개장 시각을 혼동하지 않는다.
  여러 날 이월된 보유의 원래 예정일을 검증할 자료가 없으면 평일 계산으로 만들지 않는다.
  지연 사유와 실제 청산 결과는 원래 개장 청산 성과와 구분할 근거를 남긴다.

## 소유세대와 주문 경계

청산은 기존 `EXP_D` 전략 및 소유세대로 `automated_orders`와 공용 주문 대기열을 통한다.
`manual_protective_exit`로 바꾸거나 새로운 실험 arm으로 재배정하지 않는다.

- 전송 준비와 직전 검사에서 현재 보유·매도가능수량, 완전한 통합 미체결,
  미해결 매도, 현재 00 연결 세대와 원래 소유세대를 확인한다.
- 세션·시각·소유·수량·증거가 바뀌면 보류한다. 한 종목의 미확정 상태가 다른 종목의
  입증된 청산 기회를 지우지 않으며, 미확정 종목을 억지로 소유 정상으로 바꾸지 않는다.
- 정상 개장/지연 청산과 분·일자·재시작이 달라져도 같은 소유세대의 전송 시도를
  별개 신호로 재전송하지 않는다. 기존 개장 청산 시도도 확인한다.
- 접수, 응답 유실, 불확실 전송, claim만 남은 상태는 소비된 시도로 보존한다.
  과거 `not_submitted`도 명확한 미전송 증명이 없으면 임의로 재시도하지 않는다.
  부분 체결이나 ACK만으로 잔량·소유·예약을 해제하지 않는다.

이번 원소유세대별 Store claim에는 기존 금융 원장의 `NOT_SENT` 해제 증명 어댑터를
연결하지 않았다. 따라서 이 claim이 소비된 뒤에는 `not_submitted` 표기나 재시작만으로
자동 재전송하지 않는다. 앱의 기존 금융 원장에 해제 증명 기능이 전혀 없다는 뜻은 아니다.

## 보유 청산을 먼저 실행

공식 세션과 기존 소유가 확인된 보유 청산을 후보 발굴·입력 준비·확장 전략 선정보다
먼저 처리한다. 일반 후보의 batch 크기를 이유로 보유 청산을 뒤로 밀지 않는다.
같은 순회의 일반 후보 스캔에서 이미 처리한 보유를 다시 주문하지 않는다.

장전 준비가 개장을 가로지르거나 조회가 오래 걸리면 현재 시각과 공식 세션을 다시 확인한다.
순회 시작 시각을 계속 현재 시각으로 사용하지 않는다. 보유 우선 처리는 요청 속도 제한,
공용 세션·큐, 수량·소유 대사와 주문 직전 검사를 우회하는 병렬 전송을 뜻하지 않는다.

## 검증과 운영 경계

회귀는 임시 원장·배정 DB와 가짜 브로커/공용 큐, 전진 시계로 수행한다. 개장 109초 경과,
일반 batch보다 많은 보유, 순회·재시작 중복, 기존 불확실 시도, 부분 체결/미체결,
소유·수량·00·세션 변경, 지연 개장·휴장·종료와 실전 차단을 확인한다.
원래 매수·배정·고유 체결을 재작성하거나 테스트 결과를 운영 체결로 기록하지 않는다.

수신기 재시작만으로 구버전의 지난 청산창이 다시 열리지 않는다. 종료일 재대사 A/B/C와
별개의 주문 경로 수정이며, 운영 반영에는 정확한 manifest의 당일 전체 격리 검증과
사용자가 정한 배포·백업·claim 조건이 별도로 필요하다. 소스 수리 자체는 배포나 주문 승인이 아니다.
