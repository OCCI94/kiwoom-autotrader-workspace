# 안정·처리량 단계별 계약

2026-11-03 통합 요청에 따른 소스 준비 문서다. 배포·설치·실제 발송은 별도 승인 사항이다.
현재 `paper_experiment_v1`의 14개 arm, 40보유, 테마5, 이월20, VSS8, TTL180,
건당 `min(300000, 실제현금//45)`를 유지한다. 새 코드를 준비했다는 사실은 운영 활성화가 아니다.

## 안정 우선

- 일반 코드 배포는 KST **화·목 08:30 미만 또는 15:40 이후**, 공식 세션 밖에서만 허용한다.
  날짜 해석은 KST 화·목 당일이다. 수요일 새벽을 화요일 배포 창으로 확장하지 않는다.
  각 날짜의 정상 배포 claim은 1회이며 실패·결과 미확정도 보존한다. 추가 실행은 별도 일회성
  예외 승인 토큰이 필요하다. 장전 공식 세션 증거가 없거나 오래되면 중단한다.
- 소스 SHA·PID·paper 모드·유효기간과 사용자 코드 배포 승인을 결합하고 첫 변경 전과 교체 직전에
  다시 확인한다. 운영 원장을 과거 백업으로 덮어 복구하지 않는다.
- `stability_watchdog.py`는 별도 감시기 소스다. 운영 원장은 `mode=ro/query_only`로 읽으며
  주문·고유00·REST 평균·불확실 intent를 구분한다. 기본 점검은 발송·재시작을 하지 않는다.
  승인된 알림을 켤 때만 기존 키체인·페어링 Telegram 경로를 사용한다. 상태가 같은 정상 대기는 조용히 유지한다.
- 매분 프로세스 생존·00 ready·완료 tick 경과 120초·위험 증거 만료·미체결·마커를 관측한다.
  08:50 입력/달력/arm, 15:35 당일 청산 대상, 16:00 KPI/깔때기 점검을 별도 claim으로 구분한다.
  의도된 이월 arm을 당일 미청산 장애로 잘못 세지 않는다. 지연 개장·휴장은 실제 공식 세션을 따른다.
- 수신기의 실제 ready/tick/신호 기록과 등록 제어 경로의 변경 감사를 해시로 연결한다.
  분당 관측 비율은 연속시간 ready 비율과 구분한다. 누락·쓰기 실패·원문 불일치·설명되지 않은
  보호 파일/PID 변화가 있으면 KPI는 미확정이다. 데이터가 없다는 이유로 유실/개입을 0회로 만들지 않는다.
- 안정 목표는 ready 99.5% 이상, tick 최대 간격 120초 미만, 운영상 유실 0, 기록된 운영 개입 0인
  **실제 공식 거래일 10일 연속**이다. 달력의 이전 거래일 연결을 검증한다. 소스 테스트·과거 성공일
  추정으로 카운트를 채우지 않는다. 재시작 횟수는 원인과 함께 별도로 보고한다.

## 핫리로드의 현재 준비 범위

`config/paper_hot_policy.py`의 승인된 정책 로더를 주입하는 소스 연결점만 준비한다.
현재 수신기에 자동 연결하거나 승인 파일을 만들지 않는다. 정책은 다음 주기에 고정하고
주문 전송 직전에 같은 epoch인지 다시 확인한다. 이전 배정과 소유 포지션 청산은 유지한다.

| 항목 | 현재 v1에서 준비한 지원 | 별도 새 어댑터가 필요한 것 |
| --- | --- | --- |
| 후보 풀 | 기본 종목을 보존한 기존 30/40 범위 조정 | 동적100 / 진입80 |
| arm | 기존 non-R arm의 신규 진입만 pause | 신규 arm 추가·기존 소유 청산 해제 |
| 임계치 | 현재 버전의 규칙 보존 | A/B/E 임계치 변경·새 변형 |
| 금액/보유 | 기존 엄격 v1 검증 유지 | 10만원 / 60보유 |

금융 한도를 JSON만 바꾸어 우회하지 않는다. 지원하지 않는 필드는 명시적으로 거부한다.
정책 파일 준비·소스 훅·실제 다음 주기 적용은 서로 다른 상태로 보고한다.

## 차기 처리량 프로필

`paper_experiment_throughput_proposal.py`는 **비활성 연구 프로토타입**이다.
현재 주문 경로와 연결되지 않았으며 모든 경로가 `can_submit=false`다.

| 항목 | 현재 운영 v1 | 승인 검토용 미래 v2 |
| --- | --- | --- |
| 보유/건당 | 40 / min(30만원,현금÷45) | 60 / min(10만원,현금÷45) |
| 관측/진입 풀 | 30 / 40 | 100 / 80 |
| 대조군 R | 원래 불변 배정·시각 | 사전 고정 후보에서 하루 10회 계획 |
| 평가 | 종목·일자별 최초 arm 배정 | 전 arm 평가 후 실제 동시 신호 중 기록된 추첨 |
| ORB | 실제 동일 구간14세션 | 별도 버전에서5→14, 실제 확보 분모 기록 |
| 변형 | 현재14개 | B 1.5/2/3, A·E 각2개 추가 검토 |

R의 10회는 게이트를 통과해야 하는 계획 시도 수다. 현금·원장·ready·위험·시장 무결성을
우회해 10건 체결을 보장하지 않는다. 놓친 시각을 과거 신호로 재생하지 않는다.
후보·종목·시각·보유시간의 시드와 사전 유니버스 해시를 기록한다.
같은 시각의 충돌 추첨에는 실제 PASS 증거만 넣으며 R/A 실현 비율 15% 조건을 분리한다.

원래 B와 같은 식인 B2 변형도 새 시도 목록에서 명시해 상관된 검정을 숨기지 않는다.
현재 v1 배정·성과와 미래의 동시 평가 설계를 합쳐 같은 무작위 실험 성과라고 하지 않는다.
실행 어댑터 통합은 안정 기준 달성·별도 승인·배포 창·전체 회귀 후의 다음 단계다.

## 실제 측정과 일정

1. 1주차: 배포 제한·감시기·복구/입력 검증·KPI/깔때기 및 신규 설정 검토본을 준비한다.
   승인 전에는 감시기를 설치하거나 실제 알림을 보내지 않는다.
2. 2주차: 지원 가능한 핫리로드와 입력 생산자를 확인하고 실제 완전 관측일의 안정 카운트를 시작한다.
   자료가 없는 날을 0장애로 처리하지 않는다.
3. 3~4주차: 실제 10거래일 기준을 통과한 뒤 동시 평가·변형의 실행 어댑터를 통합하고 승인된 창에 배포한다.
   데이터가 부족하면 달력상 몇 주가 지났다는 이유로 활성화하지 않는다.
4. 매일16:00 arm별 관측→배정→평가→신호→의도→접수→고유00 및 KPI를 기록한다.
   금요일에는 KPI·깔때기 추이를 한 장으로 요약한다. 미계측은 미확정이며 실제 비용 미확정 Net도 유지한다.

## 테마와 장후 연구

연구 `weekly_theme_taxonomy.py`는 보존된 완전 페이지와 공식 장후 증거로 새 분류표 후보를 만든다.
TR은 프로젝트 `tr_docs/ka90001.md`(테마그룹), `ka90002.md`(구성종목), `ka10099.md`(업종명 포함 종목목록)를 따른다.
페이지·커서·원문 projection 해시·시장 충돌을 검증하며 기존 집중 한도와 같은 family 의미를 사용한다.
다른 시장/ETF 등 두 주식 마스터에 없는 종목은 미대사 목록에 표시한다. 상장 자격이나 위험 통과로 바꾸지 않는다.
미분류10% 목표의 실제 달성 여부는 장후 실자료와 사전 고정 분모로 측정한다.

2부 급등 전조 연구와 야간 메시지 작업은 공식 장 마감 후에 시작한다. 현재 실제 운영 수집을
추가 호출하지 않는다. 기존16:00 저장 manifest·claim을 공유하고 미지원 TR은 HALT로 남긴다.
야간 첫 실행은 파일만 만들고, 300건 라벨 초안은 검토 필요로 전달하며 절반은 봉인한다.
설치·실제 발송·분류표 교체·주문 후보 연결은 별도 승인 전 실행하지 않는다.
