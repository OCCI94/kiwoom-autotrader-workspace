# 모의 전략 진입 감시 풀

`paper_strategy_entry_pool_limit`는 모의 다중 전략의 신규 진입 감시 풀 크기다.
정수 `1..40`만 허용하며, 키가 없는 기존 파일의 기본값은 이전 확장 감시 풀
상한과 같은 `30`이다. 이번 25종목 기본 풀과 동적 후보를 합쳐 40종목을
감시하려면 모의 옵션 파일에 `40`을 명시한다. 설정 읽기만으로 기존 파일을
이관하거나 운영 옵션을 바꾸지 않는다.

- 설정된 기본 종목을 먼저 유지하고, 중복을 제거한 동적 후보를 남은 자리에
  편입한다. 설정 기본 풀 자체가 전체 감시 상한보다 크면 조용히 잘라내지
  않고 설정 오류로 보류한다.
- `paper_dynamic_candidate_limit`는 순위 공급자의 후보 반환 한도다. 기존
  `15..30` 범위를 유지하므로 `20`개를 받아도 기본 풀 25종목과 총 상한
  40종목이면 신규 동적 편입 자리는 최대 15개다.
- 보유·미체결 종목의 청산 감시는 신규 진입 풀 상한과 별도로 먼저 실행한다.
  풀에 포함됐다는 사실은 매수 신호나 주문 허가를 의미하지 않는다. 실제 주문은
  현재 자료·상품 분류·거래 가능성·동일 세션·원장 대사 검증을 계속 통과해야 한다.
- 이 값은 동시 보유 상한을 늘리지 않는다. `paper_max_concurrent_positions=8`,
  종목별 전 전략 합산 원금 100만원, B3 첫 진입 50%와 기존 미체결/의도 대사는
  각각 독립된 제약이다. 기본 추가 감시 목록은 최대 25종목, 종목별 예산은
  100만원 이하이며 중복 코드는 거절한다.
- 실전 모드에는 동적 감시를 활성화하지 않으며 이 값의 유효 반환은 `0`이다.
  신규 키는 `paper-strategy-options.json`에만 저장하고 수집기와 공유하는
  `settings.json`에 쓰지 않는다.

## 이전 소스에서 전체 업그레이드할 때

이번 풀 확장용 배포 후보는 아래 전체 업그레이드를 사용하지 않는다. 현재
설치된 수신기 소스를 복제하고 풀 설정·감시 변경만 덧붙인다. 따라서 후보에는
시간창/TTL 코드 및 해당 옵션 키가 없고, 종전 `09:00..15:30` 동작과 자동
취소 비활성을 유지한다. 운영 모의 옵션에는 풀 상한 `40`과 추가 감시 종목만
병합한다. 별도 `collector-runtime`의 기존 설정 로더는 공유 `settings.json`만
읽고 모의 수신기 옵션 파일을 읽지 않음을 복제한 소스로 격리 검증했다.

2026-10-31 감사 시점의 설치된 수신기에는 신규 최초 진입 시간창 및 TTL
옵션이 아직 없었다. 준비된 전체 소스를 적용하면, 키가 없는 경우의 새로운
모의 최초 진입 기본 종료가 `15:20`이므로 기존 `09:00..15:30` 동작과 다르다.
풀 확장만 적용하면서 종전 시간을 유지하려면 승인된 배포의 모의 옵션에
다음을 함께 명시해야 한다.

```json
{
  "paper_strategy_entry_pool_limit": 40,
  "gdcrs_entry_start_time": "09:00",
  "gdcrs_entry_end_time": "15:30",
  "gdcrs_unfilled_buy_ttl_seconds": 0
}
```

이는 기존 전체 모의 옵션에 병합하는 값이며 위 네 항목만으로 기존 파일을
덮어쓰는 예시가 아니다. 시간창은 최초 골든크로스 매수에만 적용된다.
기존 B3 추가 매수 및 S2~S4의 별도 마감 규칙은 이 시간 설정으로 확대되지
않는다. TTL `0`은 자동 취소·추가 TTL 조회를 하지 않는다. MA 설정은 여전히
공유 키 `gdcrs_short_period=5`, `gdcrs_long_period=20`이며 변경하지 않는다.

구현·격리 테스트와 실제 운영 적용은 구분한다. 이 문서와 소스 변경 자체는
설정 변경, 프로세스 재시작 또는 매매 실행을 수행하지 않는다.
