# ai-stock

Mac에서 텔레그램 명령을 계속 수신하며 키움 인증, 종목·계좌 조회, 매수·매도 주문,
명령 예약과 채널 글 수집을 수행하는 Python 프로젝트입니다. 모의·실전 로그인과 토큰 갱신,
일자별 메시지 팩터, 오프라인 예제 전략을 지원합니다. 주문 명령은 현재 로그인한 환경의
키움 서버에 전송합니다.

## 실행과 최초 설정

설정이 완료된 Mac에서는 **`start.command`를 더블클릭하면 텔레그램 명령 수신을 시작**합니다.
이미 자동 실행을 설치했다면 백그라운드 수신기를 시작하며 중복 실행하지 않습니다.
설치 전에는 실행한 터미널에서 계속 수신합니다.

수신 프로세스가 시작되면 텔레그램으로 시작을 알리고 저장된 모의 키로 `login paper`를
자동 실행합니다. 결과를 텔레그램과 터미널에 보고하고, 성공하면 일일 토큰 갱신을 예약한 뒤
명령을 계속 기다립니다. 시작 모드는 모의투자이며 실전은 실행 중 `login real`로 전환합니다.

| 실행 파일 | 용도 |
| --- | --- |
| `setup-mock.command` | 모의투자 App Key·App Secret 인증 후 키체인에 저장 |
| `setup-real.command` | 실전투자 App Key·App Secret을 별도 키체인 항목에 저장 |
| `setup-telegram.command` | BotFather 봇과 본인 개인 채팅 연결 |
| `telegram-autostart-install.command` | Mac 로그인 시 봇 수신 자동 실행 등록·시작 |
| `start.command`, `telegram-listen.command` | 텔레그램 명령 수신 시작 |
| `console.command` | 터미널에서 수신하며 로그인·갱신 결과와 토큰 확인 |
| `connect-mock.command` | 모의 인증 후 국내 삼성전자·미국 애플 시세를 한 번 조회 |
| `telegram-account-setup.command` | 개인 텔레그램 계정 연결·수집 채널 선택 |

처음 사용할 때는 모의 키 저장 → 봇 연결 → 자동 실행 설치 순서로 진행합니다.
키 입력은 숨김 방식이므로 입력한 글자가 보이지 않아도 붙여넣고 Enter를 누르면 됩니다.
실전 로그인은 `setup-real.command`에서 실전 키를 따로 등록한 뒤 사용할 수 있습니다.

모의·실전 키는 각각 `com.local.kiwoom-autotrader.mock`,
`com.local.kiwoom-autotrader.real` 키체인 서비스에 저장합니다. 새 키의 인증에 성공한 뒤
저장하므로 실패한 입력으로 기존 키를 덮어쓰지 않습니다. 키를 설정 JSON이나 명령줄 인자에
기록하지 않습니다. 키체인 접근이 필요하면 macOS의 안내를 따릅니다.

프로젝트 폴더에서 Python 3.11 이상으로 실행할 수도 있습니다.

```sh
# 하위 명령을 생략하면 텔레그램 수신 시작
python3 -m kiwoom_autotrader
python3 main.py

# 모의 키 저장 여부 확인 또는 등록
python3 -m kiwoom_autotrader credentials-status
python3 -m kiwoom_autotrader credentials-setup

# 실전 키 저장 여부 확인 또는 등록
python3 -m kiwoom_autotrader credentials-real-status
python3 -m kiwoom_autotrader credentials-real-setup

# 모의 인증·국내/미국 시세를 한 번 조회
python3 -m kiwoom_autotrader connect
```

현재 Mac의 실행 파일은 Codex 번들 Python을 우선 사용합니다. `python3`가 없다면 아래
경로를 대신 사용할 수 있습니다.

```sh
"$HOME/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/bin/python3" -m kiwoom_autotrader
```

## 텔레그램 명령

`setup-telegram.command`에서 봇 토큰을 입력하고 연결 링크를 열어 본인 Telegram에서
`시작(Start)`을 누릅니다. 일회용 연결 코드가 일치하는 개인 채팅을 등록하고 확인 메시지를
한 번 보냅니다. 봇 토큰과 채팅 정보는 `com.local.kiwoom-autotrader.telegram` 키체인
항목에 저장합니다. 이 봇 연결에는 개인 계정의 로그인 코드나 비밀번호를 사용하지 않습니다.

| 텔레그램 명령 | 동작 |
| --- | --- |
| `login paper` | 모의투자 서버에서 토큰을 발급받아 로그인 |
| `login real` | 실전투자 서버에서 토큰을 발급받아 로그인 |
| `login renewal 8:50` | 매일 토큰 갱신 시각을 한국 시간 08:50으로 변경·저장 |
| `srch {종목코드 또는 종목명}` | 현재가·거래량·시가·고가·저가·전일대비 조회 |
| `buy {종목코드 또는 종목명} {수량} [지정가]` | KRX 매수. 지정가를 생략하면 시장가 |
| `buy {종목코드} max {금액}` | 현재가로 수량을 계산하고 예산 이내의 지정가 매수 |
| `sell {종목코드} {수량}` | KRX 시장가 매도 |
| `report`, `r` | 국내 계좌 자금 현황과 보유 내역 조회 |
| `rank`, `rank {1~4}` | 거래대금·상승률·거래량·인기검색 메뉴와 상위 20종목 |
| `rank {번호} cmd {개수} {명령}` | `( )`에 종목코드를 넣어 상위 1~20종목에 순차 실행 |
| `gdcrs intv {단기} {장기}` | 1분봉 SMA 기간 각각 1~60 저장. 기본 5/20 |
| `gdcrs add {코드} {금액}`, `gdcrs list` | 골든크로스 종목·예산 등록 및 등록순 목록 |
| `gdcrs remove {번호}`, `gdcrs clear` | 현재 목록 번호로 삭제하거나 목록 전체 비우기 |
| `start gdcrs`, `stop gdcrs` | 등록 종목의 골든크로스 예산 매수 감시 시작·정지 |
| `start ddcrs`, `stop ddcrs` | 원장으로 입증된 자동전략 소유 수량의 데드크로스 매도 감시 시작·정지 |
| `IP` | 현재 외부 공인 IP 확인 |
| `mkhr {시작시각} {종료시각}` | 장 시작·종료 시각 설정. 기본 09:00~15:30 |
| `stts` | 예약을 포함한 현재 설정 전체를 JSON으로 표시 |
| `stts default` | 설정을 기본값으로 되돌리고 등록한 예약 삭제 |
| `rsv {시각} {명령}` | 한국 시간 기준 평일 매일 실행할 명령 등록 |
| `rsv list` | 등록된 예약의 ID·시각·명령 확인 |
| `rsv remove {ID}` | 해당 예약 삭제 |
| `power off` | 종료 응답 후 명령 수신과 채널 수집 종료 |
| `help`, `/help`, `/start`, `도움말` | 모든 명령과 사용법 안내 |
| `status`, `/status`, `상태` | 모의투자 인증과 국내·미국 시세 연결 확인 |
| `top`, `/top`, `상위20`, `거래대금` | 코스피·코스닥 일반기업 주식 거래대금 상위 20종목 |
| `channels`, `/channels`, `채널` | 선택 채널과 수집 현황 |
| `posts`, `/posts`, `채널글` | 수집한 최근 채널 글 5개의 미리보기·원문 링크 |

명령의 앞뒤 공백을 제거하고 영문 대소문자를 구분하지 않습니다.
예를 들어 `  LOGIN PAPER  `도 `login paper`와 같습니다. 등록된 개인 채팅에서
본인이 보낸 새 명령만 처리하며 임의의 코드나 채널 글을 명령으로 실행하지 않습니다.

`login paper`는 `https://mockapi.kiwoom.com`, `login real`은
`https://api.kiwoom.com`에서 토큰을 받습니다. 발급 결과와 투자 구분은 텔레그램과
터미널에 보고하고, 토큰과 현재 투자 구분은 수신 프로세스의 메모리에 보관합니다.
로그인 전환이 실패하면 기존 로그인 상태를 유지합니다. 기존 토큰이 이미 만료됐다면
재로그인이 필요하다고 알리고 조회·주문에 사용하지 않습니다.

`au10001` 응답의 필수 만료일(`expires_dt`) 누락·잘못된 형식·이미 지난 만료일은 인증
성공으로 처리하지 않습니다. 문서에는 만료일의 시간대가 없으므로 이 프로그램은 한국
시간으로 해석합니다. 로그인 응답이 예약 시각을 지나 도착해도 즉시 중복 갱신하지 않도록
다음 갱신은 인증 완료 시각을 기준으로 정합니다.

로그인 후에는 **매일 08:55(Asia/Seoul)**에 같은 투자 구분으로 토큰을 갱신합니다.
`login renewal H:MM` 또는 `login renewal HH:MM`으로 00:00~23:59 중 원하는 시각을
설정할 수 있습니다. 이 설정은 재시작 후에도 유지됩니다. 갱신 성공·실패는 텔레그램과
터미널에 보고합니다. 예약 갱신 실패 시 반복 요청하지 않으며 `login paper` 또는
`login real`을 다시 보내 수동으로 재시도할 수 있습니다.

토큰 원문을 보려면 `console.command`를 실행한 터미널에서 명령 수신을 유지한 채
Telegram으로 로그인 명령을 보냅니다. 대화형 터미널에는 성공 여부와 토큰을 출력하며,
백그라운드 로그나 파일로 리다이렉트한 출력에서는 토큰을 가립니다. 텔레그램 응답에는
토큰 원문을 넣지 않습니다. 콘솔 모드는 기존 백그라운드 봇 수신기를 먼저 중지합니다.

수신기를 재시작하면 이전 토큰·투자 구분은 사라지고 저장된 모의 키로 새 로그인을 시도합니다.
이전에 실전으로 전환했더라도 다시 시작할 때는 모의투자로 로그인합니다.
현재 `/status`, `/top`, `connect`, `mock-quote`는 별도의 모의 조회 기능입니다.
`srch`, `report`/`r`, `buy`, `sell`은 현재 메모리의 로그인 구분과 토큰을 사용합니다.
`login real`로 전환한 뒤의 `buy`·`sell`은 실전 주문입니다.

`/top`은 종목 분류를 이용해 ETF·ETN 등을 제외하고 우선주는 포함합니다. KRX·NXT 통합,
관리종목 포함 기준이며 거래대금은 억원으로 표시합니다. 분류와 순위 조회에 몇 초 걸릴 수 있습니다.

## 종목 조회·주문·계좌 보고서

`srch 005930` 또는 `srch 삼성전자`로 국내 종목을 조회합니다. 응답은 종목명·코드와 함께
현재가, 거래량, 시가, 고가, 저가, 전일대비의 여섯 지표를 이모지로 구분해 보여줍니다.
종목명은 코스피·코스닥 목록에서 공백과 영문 대소문자를 정규화해 정확히 일치하는 이름을
찾습니다. 부분 일치나 같은 이름의 여러 종목이 있으면 후보를 안내하고 임의로 선택하지 않습니다.
처음 이름으로 조회할 때는 목록을 가져오는 시간이 추가로 걸릴 수 있습니다.

매수는 종목코드 또는 종목명을, 매도는 6자리 종목코드를 받습니다. 공백을 포함한 매수
종목명은 따옴표로 묶습니다. 수량과 지정가는 12자리 이내 양의 정수로 입력합니다.

```text
buy 005930 1
buy 삼성전자 1 70000
buy 005930 max 100000
sell 005930 1
```

매수 지정가를 생략하면 시장가(`trde_tp=3`), 가격을 입력하면 보통 지정가(`trde_tp=0`)로
요청합니다. 매도는 시장가입니다. 주문 거래소는 KRX이며 응답에는 모의·실전 구분, 종목,
수량, 주문 유형과 주문번호를 표시합니다. 주문 접수는 체결 완료를 뜻하지 않습니다.
전송 후 결과가 불확실하면 자동으로 같은 주문을 다시 보내지 않으므로 증권사 주문내역에서
접수 여부를 확인합니다.

`buy 005930 max 100000`은 현재가를 조회해 `수량 = 금액 // 현재가`로 계산합니다.
가격 필드의 상승·하락 부호는 제거하고 원 단위 정수 가격을 사용합니다. 현재가를 지정가
상한으로 삼아 `수량 × 지정가 ≤ 입력 금액`을 지킵니다. 현재가가 공통 KRX 가격격자에 맞지
않으면 `ka10004`의 최근 호가에서 양의 잔량이 있는 가격 중 현재가 이하 최고 가격을 확인해
지정가로 사용합니다. 가격을 추측하거나 올리지 않으며, 원래 현재가로 계산한 수량을 늘리지
않습니다. 호가 확인 실패·오래된 시각·세션/중지 상태 변경 시 주문하지 않습니다. 상품별 호가단위를
추측하는 대신 실제 표시호가를 확인하며, 응답은 조회가와 실제 지정가를 구분합니다.
가격격자 확인은 [KRX 호가 규정](https://regulation.krx.co.kr/contents/RGL/03/03010100/RGL03010100T3.jsp)을 참고합니다.
시장가 주문은 시세 변동으로
이 상한을 보장할 수 없어 지정가를 사용합니다. 수수료 등 부대비용은 이 금액 계산에서 제외합니다.
1주도 살 수 없는 금액이나 잘못된 시세에는 주문을 보내지 않습니다. 지정가 주문이므로 미체결·
부분 체결될 수 있으며, 응답에 예산·수량·지정가·주문금액·남은 예산과 접수번호를 표시합니다.

`report` 또는 `r`은 예수금, 출금가능금액, 주문가능금액, D+1/D+2 추정예수금과
총매입·총평가·평가손익·추정예탁자산을 보여줍니다. 보유 내역에는 종목명·코드, 수량,
매매가능수량, 매입가·현재가, 평가금액과 손익을 표시합니다. 계좌번호와 계좌 소유주 이름은
응답에 넣지 않습니다. `kt00001` 추정조회와 `kt00018` 합산조회로 가져온 **국내 계좌·KRX 기준**입니다.

연속조회 결과를 모두 가져온 뒤 보고하며, 합계 금액은 페이지별로 더하지 않습니다.
조회 한도를 넘거나 후속 페이지에 오류가 있으면 전체 내역을 확인하지 못했다고 알립니다.
누락값은 0으로 대체하지 않고 `미제공`으로 표시하며, 명시적인 빈 보유 목록과 구분합니다.
여러 요청으로 조회하므로 완전히 같은 시점의 잔고는 아니며, 긴 내역은 여러 메시지로 나눕니다.

## 장 시간·설정·명령 예약

`mkhr 9:00 15:30`으로 장 시간 설정을 저장합니다. 시작·종료 시각은 00:00~23:59 범위이고
시작이 종료보다 빨라야 합니다. `mkhr`는 시간 설정을 저장하는 기능이며, 이 시간 밖의
주문을 프로그램에서 자동 차단하는 조건은 추가하지 않습니다.

`stts`는 현재 설정 전체와 등록된 예약을 JSON으로 보여줍니다. `stts default`는 모든
일반 설정을 기본값으로 되돌리고 예약을 삭제합니다. 실행 중인 토큰 갱신 시각에도 기본
08:55를 즉시 적용하며, 키체인 인증정보나 수집한 채널 글을 삭제하는 명령은 아닙니다.

예약은 한국 시간의 24시간제로 등록하며 ID로 관리합니다.

```text
rsv 8:55 login paper
rsv 15:20 report
rsv list
rsv remove 1
```

예약 명령은 **월~금 매일** 해당 시각에 실행하고 텔레그램으로 실행을 알립니다.
토요일·일요일은 건너뛰며, 거래소 휴장일 달력은 아직 연결하지 않았으므로 평일 공휴일도
예약 실행 대상입니다. 예약은 프로그램의 수신 루프가 실행 중일 때 동작합니다.
중지·재시작 전에 이미 지난 예약 시각은 나중에 몰아서 실행하지 않습니다.

예약 목록은 실행 설정의 `reservations`에 저장하고, 날짜별 실행 표식은
`config/data/reservation-state.json`에 따로 기록합니다. 작업을 수행하기 전에 표식을 저장하여
같은 예약을 같은 날 중복 실행하지 않습니다. 실행 도중 중단되거나 서버 전송 결과가
불확실해도 해당 예약을 자동 재시도하지 않습니다.

프로그램 시작 또는 예약 등록 시각보다 이미 지난 당일 예약은 다음 평일부터 적용합니다.
예약 안에 다시 `rsv`를 넣을 수 없습니다. 등록할 명령의 세부 인수는 일반 명령과 같은
형식으로 입력하며, 등록할 때와 실행 직전에 검사합니다. 조회·주문 예약에는 실행 시점의
로그인 구분과 토큰을 사용합니다.

## 자동 실행과 종료

`telegram-autostart-install.command`를 한 번 실행하면 즉시 수신을 시작하고, 이후 Mac을
재시작해 **사용자 로그인 시 자동 연결**합니다. 터미널과 Codex를 열어 둘 필요는 없습니다.
네트워크 등으로 비정상 종료하면 macOS가 재실행하며 반복 실행은 30초 간격으로 제한합니다.
Mac이 깨어 있고 인터넷에 연결되어 있어야 하며 로그인 전이나 잠자기 중에는 수신하지 못합니다.

`power off`를 보내면 응답 후 봇 수신과 개인 계정 채널 수집을 종료하고 키움 메모리
로그인을 해제합니다. 정상 종료로 처리하여 즉시 재실행하지 않습니다. Mac 자체를 끄는 명령은
아니며, 설치된 자동 실행은 유지되어 다음 Mac 로그인 때 다시 시작하고 모의 로그인을 시도합니다.
그 전에 다시 사용하려면 봇 수신과 채널 수집을 각각 시작할 수 있습니다.

```sh
python3 -m kiwoom_autotrader telegram-listen
python3 -m kiwoom_autotrader telegram-account-listen
```

`telegram-stop.command`는 봇 수신만, `telegram-account-stop.command`는 채널 수집만
중지합니다. 자동 실행 자체를 해제하려면 각각 `telegram-autostart-remove.command`,
`telegram-account-autostart-remove.command`를 사용합니다. 저장한 키와 채널 기록은 유지됩니다.

실행용 소스와 상태는 `~/Library/Application Support/KiwoomAutotrader/`에 두며
프로젝트 소스를 수정한 후에는 자동 실행 설치를 다시 실행해 실행용 복사본을 갱신합니다.
개인 계정 수집기의 자동 실행 설정은 연결 화면에서 채널을 선택하고 수집을 시작할 때 설치합니다.

```sh
python3 -m kiwoom_autotrader telegram-autostart-install
python3 -m kiwoom_autotrader telegram-autostart-status
python3 -m kiwoom_autotrader telegram-account-status
```

봇 처리 위치는 응답 전에 저장하여 같은 명령이 재시작 후 반복 실행되지 않도록 합니다.
전송 결과가 불확실한 응답은 자동 재전송하지 않습니다. 수신기 시작 전에 보낸 명령은
처리하지 않으므로 다시 연결한 뒤 명령을 보내세요. 다른 수신 프로그램의 기존 웹훅 설정은
자동으로 변경하지 않습니다. 봇 상태 파일에는 메시지 본문이나 토큰을 기록하지 않습니다.

## 개인 계정으로 채널 글 수집

봇과 별개로 개인 Telegram 계정을 연결하면 선택한 방송 채널의 과거 글과 새 글을 수집합니다.
`telegram-account-setup.command`를 실행하면 이 Mac에서 접근하는 연결 화면이 열립니다.

1. [Telegram API development tools](https://my.telegram.org/apps)에서 발급한
   개인 계정용 `api_id`, `api_hash`를 입력합니다.
2. `QR 코드로 연결`을 누르고 휴대폰 Telegram의 설정 → 기기 → 데스크톱 기기 연결에서
   QR 코드를 스캔합니다. 필요하면 2단계 인증 비밀번호를 입력합니다.
3. 전화번호 방식도 지원합니다. 이 경우 국가번호를 포함한 전화번호와 Telegram으로 받은
   숫자 인증코드를 사용합니다.
4. 가입한 채널 목록에서 수집할 채널을 선택하고 `선택한 채널 수집 시작`을 누릅니다.

현재 알림 봇과 연결한 본인 계정만 인증합니다. API 설정과 로그인 세션은
`com.local.kiwoom-autotrader.telegram-account` 키체인 항목에 보관하며 일반 `.session`
파일을 만들지 않습니다. 전화번호·인증코드·비밀번호를 프로젝트 파일이나 로그에 저장하지 않습니다.
개인 대화나 단체방 전체를 읽지 않고 선택한 방송 채널만 수집합니다.

처음에는 최근 100개 글을 저장한 뒤 기본 60초 간격으로 채널별 새 글과 더 오래된 글을
각각 최대 100개씩 이어서 조회합니다. 전체 수집 개수 제한은 없으며 재시작하면 저장한
처리 위치부터 이어갑니다. Telegram의 요청 대기 지시를 따르므로 수집 완료 시간은 달라집니다.
이미 삭제되거나 계정에서 접근할 수 없는 글은 가져오지 못합니다.

본문·캡션·게시/수정 시각·미디어 종류·원문 링크를 저장합니다. 첨부파일은 다운로드하지
않으며 전체 과거 글의 수정·삭제를 지속적으로 대조하는 기능은 아직 없습니다.
주기적인 조회 방식으로 새 글을 확인합니다. 수집 글은 데이터이며 매매 명령으로 실행하거나
다른 채팅으로 자동 전달하지 않습니다.

계정별 SQLite DB는 `~/Library/Application Support/KiwoomAutotrader/telegram-account/`에
권한 0600으로 저장합니다. 채널 선택을 해제하면 이후 수집을 멈추고 이전 기록은 보존합니다.
선택 후 전용 LaunchAgent가 등록되어 Mac 로그인 시 다시 연결합니다.
봇 수신과 채널 수집은 별도 프로세스입니다.

연결 화면은 30분 동안 유효합니다. 닫히거나 만료되면 설정 실행 파일을 다시 여세요.
다른 개발 환경에서는 개인 계정 기능의 의존성을 설치해야 합니다.

```sh
python3 -m pip install '.[telegram-account]'
python3 -m kiwoom_autotrader telegram-account-setup
python3 -m kiwoom_autotrader telegram-account-status
```

공식 참고: [API ID 발급](https://core.telegram.org/api/obtaining_api_id),
[과거 기록 조회](https://core.telegram.org/method/messages.getHistory),
[Telethon 메모리 세션](https://docs.telethon.dev/en/stable/concepts/sessions.html).

## 일자별 메시지 데이터와 시계열 팩터

SQLite를 원본 저장소로 사용하며, 처음 관측한 내용과 이후 관측한 수정 내용을 별도 버전으로
보존합니다. 게시 시각(`published_at`), 수정 시각(`edited_at`), 해당 버전을 수집기가
관측한 시각(`observed_at`), 최초 관측 시각과 출처를 함께 기록합니다.

성공한 수집 주기마다 기본으로 수집 상태 폴더의 `daily/`에 아래 데이터를 내보냅니다.
기본 설치 경로는 `~/Library/Application Support/KiwoomAutotrader/telegram-account/daily/`입니다.

```text
daily/
  2026-10-26/messages.jsonl   게시일이 해당 날짜인 글의 관측 버전
  daily_factors.csv          일별 수집·수정·텍스트·종목코드 후보 통계
  symbol_factors.csv         일별 종목코드 후보별 언급 수
  manifest.json              시간 기준, 출처, 범위, 파일 해시와 한계
```

**원문 폴더는 한국 시간 게시일**, **팩터는 당시 이용 가능했던 정보의 날짜**를 기준으로 합니다.
팩터의 이용 가능 시각은 관측·게시·수정 시각 중 가장 늦은 값입니다. 각 날짜의 한국 시간
23:59:59까지 알려진 버전만 사용하며, 내보내기 시점이 그보다 이르면 해당 시점에서 잘라
부분 일자로 표시합니다. 같은 날 여러 버전을 관측한 글은 해당 시점의 최신 내용으로
텍스트·언급 수를 계산하고, 버전 수는 별도로 기록합니다.

예를 들어 오늘 처음 가져온 지난달 글은 지난달 원문 폴더에 정리되지만, 지난달의
백테스트 팩터에 소급해서 넣지 않습니다. 기존 DB에서 옮긴 글도 원래 관측 시각을 추측하지
않고 기존 스냅샷이라는 출처(`legacy_snapshot`)와 마이그레이션한 시각을 기록합니다.
나중에 발견한 수정 내용이 과거 일자의 팩터를 덮어쓰지 않습니다.

기본 팩터는 관측 글·신규 글·수정 글·버전 수, 관측 채널 수, 과거 게시글의 신규 수집 수,
텍스트 길이, URL 수와 명시적 종목코드 후보의 언급 수입니다. 종목코드 후보는
`KR:005930`, `A005930`, `(005930)`, `종목코드:005930`, `$AAPL` 같은 표시에서 추출합니다.
단순한 6자리 숫자·날짜·가격이나 회사 이름만으로 종목을 추정하지 않습니다.
후보는 종목 마스터와 대조하지 않았으므로 실제 상장 종목 여부가 검증된 데이터는 아닙니다.

관측이 없는 날짜를 0으로 채우지 않으며 전체 채널이나 종목을 빠짐없이 관측했다고 가정하지
않습니다. 선택 해제한 채널의 기존 관측은 연구 기록에 남습니다. 감성 점수, 수익률 라벨,
거래일 정렬과 매매 신호는 아직 만들지 않습니다. 원문은 JSONL에만 기록하고 CSV에는 집계값을
넣습니다. 파일은 0600, 내보내기 폴더는 0700 권한으로 생성하며 변경된 파일만 원자적으로 교체합니다.

프로젝트 폴더에서 수동으로 내보낼 수 있습니다. `--as-of`를 쓰면 그 시점까지 관측한 정보만
사용합니다. 반드시 `+09:00` 또는 `Z`처럼 시간대를 포함하세요.

```sh
python3 -m kiwoom_autotrader messages-export --output data/telegram
python3 -m kiwoom_autotrader messages-export --output data/telegram-asof --as-of 2026-10-26T08:55:00+09:00
```

관측 내용이 그대로이면 기존 파일을 재사용합니다. 실제 데이터 기준 시각과 부분 일자 여부는
`manifest.json`을 확인하세요. SQLite에 당시 관측 기록이 없다면 과거 기준 내보내기에서도
그 시점의 데이터를 만들어내지 않습니다.

## 일반 설정과 프로젝트 구조

엑셀 명세를 변환하려면 프로젝트 루트의 `export_tr_docs.py`와 같은 폴더에
`키움 REST API 문서.xlsx`를 놓고 실행합니다. 실행한 터미널의 현재 폴더와 관계없이
프로그램 폴더의 엑셀을 읽어 `tr_docs/`에 시트별 Markdown을 만듭니다.

```sh
python3 -m pip install -r requirements-tr-docs.txt
python3 export_tr_docs.py
```

시트명에 괄호가 있으면 괄호 안 이름을 파일명으로 사용합니다. 파일명 충돌은 안내와
변환 목록에 기록합니다. `rank` 기능의 코딩 에이전트용 지시는 `RANK_AGENT_INSTRUCTIONS.txt`에
정리했으며, 해당 지시서는 기능 구현 결과와 구분합니다.

소스 기본값은 `kiwoom_autotrader/config/data/settings-default.json`에 있습니다.
같은 폴더의 `settings.json`은 일반 설정의 형식을 위한 빈 템플릿입니다. 실행 중 변경한
설정은 `~/Library/Application Support/KiwoomAutotrader/config/data/settings.json`에 저장하며,
기본값 위에 적용합니다. 키·토큰·계정 로그인 세션은 이 JSON 파일에 넣지 않습니다.

| 설정 | 기본값 | 의미 |
| --- | --- | --- |
| `version` | `1` | 설정 형식 버전 |
| `login_renewal_time` | `08:55` | 키움 토큰 일일 갱신 시각 |
| `timezone` | `Asia/Seoul` | 갱신 및 일자별 데이터의 시간대 |
| `channel_poll_interval_seconds` | `60` | 채널 조회 간격(초) |
| `daily_message_export` | `true` | 수집 후 일자별 데이터 자동 내보내기 |
| `market_start_time` | `09:00` | 장 시작 시각 설정 |
| `market_end_time` | `15:30` | 장 종료 시각 설정 |
| `reservations` | `[]` | 평일 반복 실행할 예약 목록 |
| `next_reservation_id` | `1` | 다음 예약에 사용할 ID |

역할별 소스 디렉토리와 실행 데이터 경로는 [프로젝트 구조 가이드](STRUCTURE.md)를 참고하세요.
키움 TR 명세는 사용자 제공 Excel 원문을 기준으로 하며, 상세한 작성 규칙과 사용 중인 TR은
[tr_docs/README.md](tr_docs/README.md)에 정리했습니다.

## 모의 시세와 원본 순위 조회

아래 명령은 저장한 모의 키를 사용해 인증하고 한 번 조회합니다.

```sh
python3 -m kiwoom_autotrader mock-quote --market KR --symbol 005930 --exchange KRX
python3 -m kiwoom_autotrader mock-quote --market US --symbol AAPL --exchange NASDAQ
python3 -m kiwoom_autotrader top-turnover --market 001 --exchange 3 --limit 20
```

`top-turnover.command`와 CLI `top-turnover`는 키움 원본 순위를 출력하므로 ETF도 포함될 수
있습니다. ETF 등을 제외한 코스피·코스닥 일반기업 순위는 텔레그램 `/top`을 사용하세요.
CLI 시장 구분은 `000` 전체, `001` 코스피, `101` 코스닥이며 거래소 구분은 `1` KRX,
`2` NXT, `3` 통합입니다. `--exclude-managed`로 관리종목을 제외합니다.
`--limit`은 1~100이며 연속조회는 최대 10페이지입니다. `ka10032`의 `trde_prica`는
백만원 단위이므로 100으로 나누면 억원입니다.

모의 조회 클라이언트의 요청 간격은 인스턴스당 최소 1.05초입니다. 여기에 공용 HTTP
대기열의 1.01초 창당 최대 4회 전송 상한이 함께 적용됩니다. 같은 실행 데이터 경로를
쓰는 로컬 프로세스도 파일 잠금으로 이 상한을 공유합니다.
키 발급과 사용 신청은 [키움 REST API 포털](https://openapi.kiwoom.com/)에서 확인할 수 있습니다.

## 오프라인 예제 전략

`run-demo.command`를 더블클릭하거나 아래 명령으로 가상 데이터의 전략 흐름을 검증합니다.
예제의 `DEMO_KR`, `DEMO_US`와 가격·거래량은 인공 데이터입니다.

```sh
python3 -m kiwoom_autotrader demo --config config.example.json
python3 -m kiwoom_autotrader simulate --bars demo-result/bars.csv --config config.example.json
```

`config.example.json`의 예제는 3봉 이동평균이 5봉 이동평균을 상향 돌파하고 현재 거래량이
직전 3봉 평균의 1.2배 이상이면 1주 매수 신호를 만들며, 하향 돌파하면 전량 매도 신호를
만듭니다. 같은 종목의 다음 봉 시가에 슬리피지를 적용하여 가상 체결하고 매수 한도·현금·수수료를
검사합니다. 원화와 달러는 별도로 계산합니다. `fee_bps=5`, `slippage_bps=10`은 각각
0.05%, 0.1%의 예제 가정이며 실제 수수료표를 뜻하지 않습니다.

실행 결과는 `runs/`의 새 폴더에 `result.json`, `signals.csv`, `fills.csv`,
`rejections.csv`, `bars.csv`, `config.json`으로 저장합니다. CSV 입력에는
`market,exchange,symbol,timestamp,open,close,volume` 열이 필요하며 시간대가 포함된 봉 마감
시각으로 전체 행을 정렬해야 합니다. 기간은 입력한 봉 간격에 따라 달라집니다.
같은 종목·시각의 동일 행은 중복 제거하고 내용이 다르면 오류로 처리합니다.

시뮬레이터는 호가 단위, 부분 체결, 유동성, 세금, 휴장일, 주식분할·배당을 재현하지 않습니다.
실행마다 계좌 상태가 초기화되며 같은 시각의 자금 사용 순서는 입력 순서에 따릅니다.

```sh
python3 -m unittest discover -s tests -v
```

테스트는 대역 HTTP·키체인과 임시 DB로 인증, 명령 수신, 갱신·예약, 주문 요청, 계좌 보고서,
설정, 종료, 관측 이력, 시점별 내보내기와 시뮬레이션을 검증합니다. 테스트에서 실제 키체인에

봉을 생성하는 기능과 미체결 주문의 취소·정정·복구는 후속 구현 범위입니다.


## 이번 확장 기능

`gdcrs intv 5 20`은 종료된 1분봉 종가 5개/20개의 단순이동평균입니다. 각 값은 1~60으로
저장되며 두 감시의 시작에는 단기<장기가 필요합니다. `gdcrs clear`는 등록 목록만 비우고
평균 기간·예약·로그인·두 전략의 활성 상태를 바꾸지 않습니다. 목록 번호는 조회 당시
등록순 1부터이며 `gdcrs list`에 골든크로스 감시의 켜짐·꺼짐도 표시합니다.

`gdcrs add 005930 100000`으로 종목과 1회 신호당 예산을 등록한 뒤 `start gdcrs`로
골든크로스 감시를 켭니다. 빈 목록에서도 켤 수 있으며, 이후 `gdcrs add`나 rank 일괄
등록으로 종목이 추가될 때까지 기다립니다. 시작·등록 명령 자체로 즉시 매수하지 않습니다.
직전 관측한 완료봉에서 단기평균<=장기평균이고 새 완료봉에서 단기평균>장기평균이 된
경우에만 기존 `buy {code} max {budget}` 경로로 주문합니다. 조회한 현재가 또는 그 이하의
확인된 KRX 표시호가를 지정가로 사용하고, 수량은 원래 예산/현재가의 정수 부분으로 정합니다. 매수 원금만 예산 이내로 제한하며
수수료는 별도입니다. 예산으로 1주도 살 수 없으면 주문하지 않고 지정가 주문은 미체결될
수 있습니다. `stop gdcrs`는 골든크로스만 끄며 목록·예산·데드크로스 상태는 유지합니다.

상시 실행기의 교차 감시에는 하루 매수 횟수 제한이 없습니다. 같은 완료봉은 한 번만
처리하며, 이후 새로운 교차에서 종목별 잔여 한도 이내로 다시 매수할 수 있습니다. 별도 연구용
`paper_trial.py`의 하루 1회 시험 제한·종료 기록은 상시 실행기와 분리되어 있습니다.
선택 설정 `gdcrs_min_cross_bps`와 `gdcrs_reentry_cooldown_minutes`는 기본값 0으로 비활성입니다.
일반 설정 파일에 정수로 지정할 수 있고 `stts`로 확인합니다. 이격도는 교차 완료봉의
`(단기 SMA − 장기 SMA) / 장기 SMA × 10000` 기준이며 최초 교차가 미달이면 그 교차는
건너뛰고 소급 실행하지 않습니다. 재진입 대기는 주문 접수가 아니라 같은 모의 원장 범위·종목의
마지막 매도 체결 관측(부분체결 포함) 이후 경과 시간입니다. 활성화한 경우 체결 스트림과
전체 대기 구간을 확인할 수 없으면 자동매수를 보류하며, 실전 모드에서는 사용하지 않습니다.
이 설정은 매도나 기존 보유분의 감시를 지연시키지 않습니다.
모의 자동주문은 `paper_automation_only` 설정값과 관계없이 반드시 매수 원금 한도와 계좌 대사를 적용합니다.
`paper_automation_only=true`는 실전 자동주문을 막으며, `paper_automation_buy_cap`은
매수 지정가×수량의 건당 한도입니다(기본 1,000,000원, 설정 최대 3,000,000원,
수수료 별도). 전송 대기 중에도 이 조건을 재검사합니다. 동일 종목의 이전 자동주문이
미확정 또는 미체결이면 겹치는 자동주문을 보류합니다. 취소·정정은 자동으로 수행하지 않습니다.
같은 종목의 보유 매입금액과 신규 자동매수 지정가 원금 합계에는
`paper_automation_symbol_cap`이 적용됩니다(기본 1,000,000원, 설정 최대 3,000,000원).
건당 한도와 종목별 한도는 별도로 검사합니다. 골든크로스 종목별 `paper_budget`은
모의 세션에만 적용되며, 생략 시 기존 공통 `budget`을 사용합니다. 실전은 `budget`을 유지합니다.
예산 매수는 남은 종목별 한도로 수량을 계산하고, 주문 직전 최신 잔고로 다시 확인합니다.
보유 매입금액이 누락·모호하거나 확인되지 않으면 추가 매수는 보류합니다. 수수료는 별도입니다.
한도를 100만원보다 높인 경우 전체 미체결 조회와 주문가능액을 확인하고, 주문원금의
0.5%를 비용 여유로 확보합니다. 미확정 내부 주문은 계좌 단위로 직렬화합니다.
주문가능금액은 현금 잔액으로 단정할 수 없고, 결제 예정과 신용 등의 영향이 있을 수 있습니다.
비용 여유는 실제 수수료 확정값이 아니며 다른 기기의 동시 수동 주문과의 경합까지
완전히 막지는 못합니다. 통합 미체결 조회가 실패하거나 불완전하면 매수를 보류합니다.
이 모의 전용 설정은 수동 텔레그램 주문이나 실전 로그인 명령의 의미를 바꾸지 않습니다.
배포 템플릿은 두 감시를 끈 상태이며, 실제 계좌의 실행 설정·인증정보를 ZIP에 포함하지 않습니다.

골든크로스는 현재 로그인한 모의/실전 서버에서 KRX 당일 정규장 완료 1분봉을 사용합니다.
설정한 장 시간과 09:00~15:30의 공통 범위에서 평일에 관측하고, 장 종료 뒤에는 활성
상태를 유지한 채 다음 평일을 기다립니다. 별도 휴장일 캘린더는 없으며 당일 최신 완료봉이
없으면 주문하지 않습니다. 시작·재시작·날짜·기간·등록 목록·로그인 변경 뒤 첫 관측은 기준만
저장합니다. 진행 중인 봉, 과거 교차, 검증되지 않은 관측 공백이나 수정된 과거 봉으로 주문하지 않습니다.
등록 종목은 순환 관측하므로 종목 수나 대기열 지연으로 연속 관측을 확보하지 못하면 해당
신호를 건너뜁니다. 처리량을 넘어선 신호를 나중에 소급 실행하지 않습니다.

모의 KRX 분봉의 **내부** 1~3분 공백은 조건을 모두 충족할 때에만 직전 종가를 이어서
추론봉으로 취급할 수 있습니다. 양쪽 봉이 같은 정상 응답 페이지의 인접 원본 행이고,
같은 종목·당일 09:00~15:20 접속매매 구간의 완료봉이며, 수정 표식이 비어 있어야 합니다.
완료 여부는 응답 도착 시각이 아니라 해당 페이지의 요청 **시작 전**에 봉이 끝났는지로
검사합니다. 요청 중 분 경계를 넘어 도착한 진행 중 봉은 완료봉으로 쓰지 않습니다.
또 두 봉의 누적거래량 차이가 뒤 봉 거래량과 정확히 같아야 합니다. 한 창에서 추론은
최대 10개입니다. 원문 기준 시각·양쪽 거래량/누적량·종가와 응답 SHA를 주문 판단 근거에
남기고 실제 서버가 반환한 봉과 구분합니다. 원문 전체 응답은 판단 근거에 보관하지 않습니다.
키움 명세는 무거래 분 생략·누적량 완전성이나 VI/거래정지 이력을 보장하지 않으므로 이는
조건부 가정이며 실제 무거래의 확정 증명은 아닙니다. 어느 조건이라도 빠지거나 모순되면
판단을 보류합니다. 최신 완료봉에 오른쪽 완료 원본 봉이 없으면 추론하지 않으며, 실전
모드에서는 추론을 사용하지 않습니다. 수정 또는 관측 정보가 바뀌면 새 기준을 쌓습니다.
두 감시의 `ka10080` 조회와 연속조회 페이지는 같은 프로세스 안에서 최소 1.05초 간격을
공유합니다. 종목·세션·모의/실전 구분 없이 적용되며 공용 HTTP 전송 상한도 함께 지킵니다.
같은 완료봉 신호는 주문 전에 내구성 있는 시도 기록을 남겨 자동 재전송하지 않습니다.
주문 결과가 불확실하면 골든크로스 감시를 중단하고 알립니다. 주문내역 확인 후 명시적인
`start gdcrs`로 다시 시작하며, 일반 로그인·설정 변경은 이 중지를 해제하지 않습니다.

`start ddcrs`는 현재 보유한 KRX 현금주식을 감시합니다. 직전 완료봉에서 단기평균>=장기평균이고
새 완료봉에서 단기평균<장기평균이면 최신 매도가능수량 전량을 기존 시장가 매도로 제출합니다.
신용주식과 모호한 중복 잔고는 제외합니다. 장 시간 설정과 09:00~15:30의 공통 범위에서
평일에 동작하며 활성화 상태를 저장해 다음 날에도 이어갑니다. 별도 휴장일 캘린더는 없지만
당일 최신 완료봉이 없으면 주문하지 않습니다. 시작·재시작·설정/로그인 변경 직후에는
관측 기준만 쌓고 과거 교차를 주문하지 않습니다. 많은 종목은 순환 관측하므로 처리량을 넘으면
연속 관측을 확인할 수 없는 신호를 건너뜁니다. 주문 결과가 불확실하면 감시를 끄고 알립니다.
감지한 데드크로스가 잔고 조회 중 한 분을 넘은 경우에는 최신 완료봉과 이전 봉의 일치,
계속된 역배열, 세션·장 시간·매도가능 수량을 다시 확인하여 한 번만 주문을 시도합니다.
재검증에 실패하거나 더 오래 지연되면 주문하지 않고 사유를 `missed_signals`에 기록하고
상태·텔레그램에 알립니다. 재시작 후 기록은 알림용으로만 보존하고 주문을 재생하지 않습니다.

`GOLDEN_CROSS_AGENT_INSTRUCTIONS.txt`는 구현된 골든크로스의 요구사항과 검증 기준을
보관한 문서입니다. 실행 감시기는 `kiwoom_autotrader/trading/golden_cross.py`의
`GoldenCrossMonitor`이며, 현재 동작은 위 설명 및 관련 소스·테스트를 기준으로 확인하세요.

`rank 4 cmd 15 gdcrs add ( ) 100000`은 조회 결과의 순서대로 최대15종목을 등록합니다.
템플릿은 `srch`, `buy`, `sell`, `gdcrs add`의 종목 인자 한 곳에만 `( )` 또는 `()`를 넣습니다.
순위를 한 번 조회하고 모든 코드를 검증한 뒤 실행합니다. `_NX`/`_AL`은 기본6자리 KRX 코드로
변환합니다. 재귀 rank/rsv는 허용하지 않으며 주문 결과가 불확실하면 나머지 일괄 실행을 멈춥니다.

## 공통 통신 엔진

모든 자체 HTTP 클라이언트는 `utils/http_queue.py`의 `queued_open`을 사용합니다.
FIFO 대기열에서 임의의1초 동안 최대4개를 전송하도록1.01초 창을 적용합니다. 여러 실행
프로세스도 타임스탬프 파일 잠금을 공유하여 전송 상한을 지킵니다. 대기 중 같은 메서드·URL·
헤더·본문·타임아웃·응답 한도는 첫 요청 하나로 합치고 각 호출자에게 별도 응답 스트림을 줍니다.
이미 전송된 요청/완료 결과를 재사용하는 캐시는 아닙니다. 서로 다른 로그인 토큰·연속조회 키·
주문 수량은 합치지 않습니다. 중복 병합은 같은 프로세스의 대기열 안에서 적용합니다.
실패도 전송 횟수에 포함하고 주문·메시지를 자동 재전송하지 않습니다. Telegram long poll의
응답 대기가 다른 HTTP 전송을 막지 않도록 동시 전송을 지원합니다.

공용 WebSocket 엔진은 프로그램 생명주기당 하나입니다. 기능 모듈은
`realtime.get_websocket_engine(session)`으로 같은 엔진을 받아 `Subscription`을 등록하세요.
첫 구독에서만 연결하고 LOGIN·REG·REMOVE·PING·REAL 분배·재연결·종료를 엔진이 관리합니다.
HTTP Upgrade도 공통 대기열의 전송 슬롯을 소비합니다. 현재 분봉 감시는 REST 조회를 사용하므로
WebSocket 구독이 없으면 연결도 없습니다. Telegram 개인 계정 수집의 MTProto 통신은 별도
프로토콜이며 이 키움 WebSocket 엔진과 혼합하지 않습니다. 자세한 계약은 `realtime/README.md`에 있습니다.

`IP`는 공개 IP 조회 서비스에서 관측한 외부 주소를 표시합니다. 키움 오류8010(토큰 발급IP와
요청IP 불일치),8050(미등록IP)에만 현재IP와 조치 안내를 덧붙입니다. 일반 연결 실패를 IP 변경으로
추정하지 않습니다. VPN·분리 라우팅 환경에서는 조회 서비스와 키움이 관측하는 주소가 다를 수 있습니다.

## 체결 원장과 장 종료 결산

자동매매는 전송 전에 전략 이름과 주문 의도를 내구성 있게 기록하고 접수 주문번호를 연결합니다.
`gdcrs`, `ddcrs`와 예약 주문(`rsv#ID`, 예약에서 실행한 rank 일괄주문 포함)을 추적하며, 수동 주문에
자동 전략 이름을 임의로 붙이지 않습니다. 약10초 주기로 `kt00009` 실제 체결번호·시각·가격·수량과
잔고를 대조합니다. 네트워크 지연·대기열·여러 조회 단계가 있으면 주기는 길어질 수 있습니다.
잔고 증감만으로 체결을 만들어 내지 않습니다. `fills`와 기존 CSV는 조회한 최신 상태이고,
같은 체결번호의 수량·평균단가가 바뀌어도 이전 관측은 불변 이력에 남습니다.
모의 REST가 같은 번호로 누적수량을 갱신할 수 있으므로 누적수량 차이를 개별 체결로 만들지 않습니다.

공용 WebSocket 엔진의 주문체결 `00`을 구독하여 단위체결번호·단위체결가·단위체결량
(`909/914/915`)을 평균단가·누적수량(`910/911`)과 구분해 보존합니다.
재전송, 재연결 공백, 누락된 단위 필드도 기록하며 REST 자료와 합산해 중복 체결을 만들지 않습니다.
등록 ACK를 받지 못했거나 기록 저장에 실패하면 새 주문을 보내지 않습니다.
모의 전용 자동주문은 전송 전에 체결·잔고·동일 종목 미체결을 새로 조회하여 기록합니다.
미체결 `ka10075`의 조회 페이지도 계좌번호·관리사번 등 민감 필드를 제외하고 불변 관측
원장과 `broker-observations.jsonl`에 남깁니다. 기록 실패·불완전 조회는 주문을 보류합니다.
대사 후 수신 공백·추가 체결 관측·로그인 변경이 발생하거나 20초가 지나면 전송을 보류합니다.
재연결 후 주문을 다시 허용하더라도 과거 수신 공백 표시를 지우지 않습니다.
연결 전·끊긴 동안의 세부 체결은 서버가 다시 제공하지 않는 한 복원을 보장할 수 없습니다.
계좌번호·접근토큰·키는 체결 관측 파일에 쓰지 않습니다.

프로그램 실행 디렉터리의 `logs/YYYYMMDD.csv`에 UTF-8 BOM 형식으로 기록합니다.
필수7개 열(체결시간,종목명,매수매도,가격,수량,전략,남은수량)과 투자구분·종목코드·주문/체결번호·
잔고조회시각·상태를 함께 남깁니다. 남은수량은 체결 발견 이후 조회한 실제 보유수량이며,
여러 체결이 함께 발견되면 동일 조회시점 수량일 수 있습니다. 정확한 체결순간 수량으로 추정하지 않습니다.
골든크로스 매수는 전략 열에 `gdcrs`로 기록하며, 주문 접수를 실제 체결로 간주하지 않습니다.
백그라운드 설치본에서는 실행본의 runtime/logs 폴더가 사용됩니다. SQLite 원장과 CSV는 재배포해도 유지됩니다.
변경 전후 관측은 `logs/YYYYMMDD.execution-history.jsonl`, REST 원응답의 허용 필드와
실시간 체결 통지는 `logs/YYYYMMDD.broker-observations.jsonl`에도 보존합니다.
SQLite의 불변 이력이 원본이며 JSONL은 재생성 가능한 출력입니다. 이전 원장의 이력은
마이그레이션 시점의 스냅샷으로 표시하고 과거 부분체결 시각을 소급 생성하지 않습니다.
`logs/YYYYMMDD.execution-accounting.json`에는 단위체결번호별 가격·수량·금액,
누적 체결금액(`903`), 관측별 수수료·세금(`938/939`), REST 참고금액과의 차이를
따로 기록합니다. 명세가 비용의 누적·단위 범위를 보장하지 않아 최신 보고비용을 주문
총비용으로 단정하거나 부분체결 비용을 임의로 합산하지 않습니다. 확인된 관측분의
금액과 등록주문 전체의 금액을 구분하며, 미확인·미체결 주문이 있으면 전체 금액은 미확정입니다.

설정한 장 종료 후 CSV에 투자구분별 일일합계를 기록하고 Telegram으로 보고합니다.
장중에도 매도한 종목의 `ka10072` 비용을 사이클당 최대 4종목씩 확인하고 60초마다
재조회합니다. 새 체결·수정이 관측되면 다시 대사할 때까지 기존 확정 손익을 미확정으로
바꿉니다. 비교용 `ka10073`과 `ka10074` 계좌 합계도 원자료로 보존하지만 전체 계좌 값을 개별 전략에
나누어 배정하지 않습니다. 수수료·세금이 없거나 TR 수치가 맞지 않으면 0원으로 채우지 않습니다.
CSV의 보고 단가×수량 합계는 REST 참고금액입니다. 누적 평균단가의 반올림 때문에
증권사의 약정금액과 다를 수 있습니다. 확인된 단위체결·누적금액 합계는 별도로 표시합니다.
`ka10072`의 매입단가·수수료·세금을 해당 자동매도 범위와 대사한 계산 순손익은
그 TR 기준 값이며 계좌 전체의 최종 확정 손익을 뜻하지 않습니다.
증권사 보고 손익, 비용을 뺀 계산값, 계좌 전체 `ka10074`는 서로 구분하며 불일치를
허용오차로 덮지 않습니다. 모의 실험은 청산 후 1회 비용 자료도 보존하고 미확정 원인을 남깁니다.
`ka10074`의 총매수대금에는 아직 보유한 주식의 매수도 포함될 수 있으므로,
총매도−총매수−보고비용은 순현금흐름으로만 표시합니다. 이를 실현순손익으로
비교하거나 계좌 보고손익과 차이가 난다는 이유만으로 산술 오류라고 판정하지 않습니다.
수익률=실현순이익/매도분 매입원가×100입니다. 미실현 평가손익은 포함하지 않습니다.
수동 매도와 섞여 정확한 귀속을 확인할 수 없거나 접수 결과가 불명확한 의도가 남으면 `미확정`으로
표시합니다. 매도 체결이 없으면 실현손익0, 수익률은 해당 없음입니다. 늦게 확인된 체결은 결산을
정정하며 동일 결산은 재전송하지 않습니다. 한 투자구분에 하나의 설정 계좌를 전제로 하므로 계좌를
교체할 때는 별도 원장 디렉터리로 분리해야 합니다.

## Windows에서 실행

프로젝트 폴더 전체를 복사하고 Python3.11 이상을 설치한 뒤 `start.bat`를 실행하세요.
배치 파일은 자신의 폴더로 이동해 `.venv`를 만들고, 해당 Python의 `pip`로 `requirements.txt`를
설치한 다음 `main.py`를 실행합니다. 설치가 실패하면 프로그램을 시작하지 않습니다.

다른 컴퓨터의 인증정보는 자동으로 복사되지 않습니다. 최초 설정은 명령 프롬프트에서
`start.bat credentials-setup`, `start.bat telegram-setup`을 실행하고, 이후 `start.bat`로 시작하세요.
실전 키가 필요하면 `start.bat credentials-real-setup`을 사용합니다. Windows에서는
Windows 자격 증명 관리자에 저장하며 평문 파일로 대체하지 않습니다. 사용자별 실행 상태는
`LOCALAPPDATA/KiwoomAutotrader`에 둡니다. Mac의 launchd 자동 실행 기능은 Windows용 배치 파일에
포함되지 않으며, Windows에서는 열린 터미널에서 실행됩니다. Windows 네이티브 실행은 별도 실기
확인이 필요하며 이 Mac에서는 가짜 Windows 인터페이스와 배치 파일 정적 검사를 수행했습니다.

## 재구성 자료에서 반영한 검증·복기 도구

2026-10-25 재구성 자료를 현재 프로젝트와 비교하여 주문 당시 근거, 읽기전용 원장 감사,
분리된 과거 이력 가져오기, 연구 입력 검증을 추가했습니다. 적용 범위와 보류 근거는
`docs/HANDOFF_APPLICATION.md`에 정리했습니다. 과거 전략 숫자·예약을 현재 매매 설정으로
복사하지 않으며 실행 중인 설치본에 새 코드를 자동 배포하지 않습니다.

```sh
python main.py offline-audit --ledger logs/.execution-ledger.sqlite3 --csv logs/20261026.csv --output audit.json --html audit.html
python main.py history --help
python main.py research --help
```

위 명령은 로컬 파일만 처리하며 로그인·주문·텔레그램 전송을 하지 않습니다. JSON/HTML 결과는
새 경로에만 저장합니다. HTML은 저장된 통계를 표시하며 새로고침해도 계좌를 조회하지 않습니다.
자료가 없거나 변경 중인 DB/WAL은 `UNKNOWN`으로 남깁니다. 파일 검증 성공과 현재 계좌의
주문 준비 상태는 별개입니다.

`gdcrs`/`ddcrs`의 새 자동주문은 의도와 함께 당시 완료봉·기간·예산·설정 SHA·신호 출처·
전략 모듈 SHA를 저장합니다. 실제 전송할 지정가/시장가 구분도 함께 고정합니다. 기록에 실패하면
주문을 보내지 않습니다. 기존 주문에 당시 근거를 소급 생성하지 않습니다. 모의 체결·합성 신호·
오프라인 가상체결을 구분합니다. 자세한 내용은 `docs/DECISION_EVIDENCE.md`를 참고하세요.

과거 이력은 `docs/HISTORY_IMPORT.md`, 연구·시뮬레이션 증거는 `docs/RESEARCH_CONTRACTS.md`,
감사 화면과 상태 해석은 `docs/OFFLINE_AUDIT.md`에 설명되어 있습니다.

### 모의 세션을 이용한 로컬 연구 조회

상시 텔레그램 수신기가 실행되면 같은 사용자 Mac의 비공개 로컬 소켓을 통해 연구 수집기가 기존 모의 세션을 이용할 수 있습니다. 토큰·인증키는 실행 프로세스 메모리에만 두고 소켓으로 전달하지 않습니다. 연구 연결은 `ka10017`, `ka10023`, `ka10081`, `ka10099`에 한정하고 주문·잔고·실전 세션을 제공하지 않습니다. 0177·0168 HTS 화면 직접 조회가 아닙니다.

공유 소켓은 사용자 전용 권한과 연결자 UID를 검사합니다. 세션이 바뀌거나 만료되거나 소켓이 실패하면 수집을 중단하고 별도 모의 로그인으로 우회하지 않습니다. 요청은 하나씩 처리하고 만료 시 뒤늦게 송신하지 않습니다. 기존 단일 HTTP 대기열의 전역 전송 제한·동일 요청 병합을 유지하고 연구 요청이 자신의 TR 대기 때문에 매매를 가로막지 않도록 합니다. 같은 TR의 이미 진행 중인 응답이나 공통 전송 슬롯이 겹치면 일부 지연은 여전히 가능합니다.

이 기능은 별도 `ai-stock-research/collector.py`의 공유 경로입니다. 다른 독립 연구 스크립트나 임의 외부 프로그램은 이 연결을 사용하지 않으며, 매매 실행 중 별도 인증하지 않아야 합니다. 이 구현은 macOS에서 검증되며 Windows에서는 공유 연구 조회를 보장하지 않습니다. 종료 전 미완료 수집과 재시작 사이 관측은 소급해 기록하지 않습니다.


## 자동주문 안전·복구 소스 계약

`paper_automation_only` 기본값과 `stts default` 초기화 값은 모두 true입니다. 모의 실험,
교차 자동감시 또는 주문 예약이 활성 상태이면 `login real`을 거부합니다. 실전 자동매수의
별도 보수적 상한은 건당·종목당 100만원, 계좌 일 200만원, 종목 일 2회 및 매도 후 20분입니다.
신선한 실제 계좌·미체결·원장·00 상태가 없으면 전송하지 않습니다. 모의 실험의 40종목·테마5·
현금/45 예산 등은 실전 분기에 적용되지 않습니다. 실전 ddcrs의 검증된 소유 어댑터는 아직
지원하지 않아 자동매도를 보류합니다. 모의 ddcrs도 수동 보유나 다른 전략 소유 물량을 가져오지 않습니다.

전일 미체결은 날짜만 보고 지우지 않습니다. 완전한 브로커 주문·미체결·체결 대사가 확인된
잔량만 소멸로 구분하며 원래 주문·체결·gap 이력은 보존합니다. 마지막 입증 체결 이후의
스트림 공백은 신선한 REST 재대사 후 소유 감시를 복구할 수 있지만, 공백 중 누락 체결이나
수량 충돌은 계속 미확정입니다. 레거시 다중전략의 미확정 주문 정지는 알림과 상태에 남고,
`multi resume` 요청 후 대사가 통과해야 풀립니다. 미확정 주문 자체를 재전송하지 않습니다.
현재 모의 실험의 종목별 자동 격리·복구 정책은 별개로 유지합니다.

TTL은 gdcrs 활성 여부와 독립적으로 모든 해당 자동 모의 매수를 점검합니다. 전송되지 않음이
입증된 취소 요청만 새 불변 재시도 기록을 만들 수 있습니다. 응답 유실·취소 ACK·부분체결은
예약금 해제나 재전송 허가가 아닙니다. B3의 검증된 전량 청산은 `lot_closed`로 구분하며,
다음 진입에는 새로운 교차와 기존 예산·횟수·쿨다운·브로커 0주 대사가 모두 필요합니다.
모의 D·VSS·LDR 매수는 판단 해시로 검증된 종가 단일가 창 종료까지 유지하며, 창 근거가
없거나 무효이면 기본 180초를 사용합니다. C·GDR은 기존의 180초와 창 종료 중 이른 시각을
유지합니다. 만료 주문은 주기마다 전부 순차 검사하고 요청별 신선도·공용 호출 간격을
다시 확인합니다. 미해결 취소 정산은 로컬 수신기 로그에 10분마다 한 줄로 요약합니다.

명시적으로 승인된 수신기 정비에서는 주문 금지 마커를 유지한 채 기존 모의 공유 세션으로
완전한 주문 상세(`kt00009`, `qry_tp=0`, KRX), 현재 계좌(`kt00001`/`kt00018`), 통합 미체결
(`ka10075`, `stex_tp=0`)을 새로 관측합니다. 이 단계는 `00 ready`와 세션·스트림 연속성을
확인하며 주문 의도·예약·취소 전송이나 정산 게시를 수행하지 않습니다. 부분 응답·세션 변경·
시간 초과는 보류하고 과거 성공 응답으로 대체하지 않습니다. 전용 정비 마커는 만료되더라도
주문 금지를 자동 해제하지 않으며, 새 조회의 원문 해시·완전성·90초 신선도와 원장 보존 검증
후 배포 도구가 인계받은 마커만 해제합니다. 당일 취소 예약 해제는 실제 대사와 불변 취소
정산 게시가 완료되어야 인정합니다. 정지 상태의 마지막 PID나 잔존 `ready=true`는 현재
실행·준비 증거가 아닙니다.

날짜를 넘긴 정비는 승인에 묶인 현재 관측일과 전일 원주문일을 구분합니다. 전일 `kt00007`
완전 응답의 주문일은 보존하고 실제 요청·관측 시각은 오늘이어야 합니다. 당일 주문 상세·계좌·
통합 미체결과 함께 같은 세션 및 90초 신선도로 확인하며 자정 전 완료한 단계를 다음 날
재사용하지 않습니다. 별도로 승인된 전일 소멸 정산 단계에서만 정확한 원주문 집합의 불변
종료 증명을 추가할 수 있습니다. 이는 취소 ACK나 취소 publication과 다른 `expired` 근거이며,
원주문·체결·현금·보유·배정 행을 바꾸지 않습니다. 두 단계의 검증과 마커 인계가 끝날 때까지
명령 폴링·예약·TTL 전송·일반 전략 평가를 차단합니다. 지난 진입·청산 시각은 재생하지 않습니다.
이 계약은 준비된 소스의 동작이며 실제 운영 복구·배포 완료를 뜻하지 않습니다.

새 인계 프로토콜은 `.maintenance-cutover.lock`의 원문 해시·inode·소유자·0600 권한을
두 단계 마커와 완료 증거에 묶습니다. 수신기는 단계 실행부터 상태 게시까지, 배포 도구는
최종 검증부터 마커 제거까지 같은 비차단 파일 잠금을 사용합니다. 마커가 제거된 뒤에도
기억한 잠금 식별자를 유지하여 두 차단 장치를 신선한 원장·세션 증거로 함께 해제합니다.
이미 제거된 마커로 단계를 재실행하거나 실패 상태를 예전 완료 상태로 복원하지 않습니다.
잠금 대기는 원래 90초 증거 한도와 전체 180초 정비 한도에 포함되며, 파일 교체·심볼릭 링크·
식별자 누락은 차단합니다. 예상하지 못한 단계 오류는 비밀값을 제외한 예외 종류와 단계명만
남깁니다. 정비 마커 제거만으로 정상 전략 실행 완료를 선언하지 않습니다.

수동 매수는 100만원 상한이며 시장가 수량은 확인된 상한가로 최대 원금을 계산합니다.
가격이 없는 순위 일괄 시장가 매수는 거부하고, 금액을 확인할 수 있는 일괄 매수도 합계
100만원을 넘을 수 없습니다. 주문 예약에는 저장된 공식 현재 거래일과 실제 정규장 시작·종료
시각이 필요합니다. 휴장·지연 개장 자료가 없으면 실행하지 않습니다. 일반 조회 예약은 유지합니다.
수신기 로그의 stdout/stderr 각 줄에는 KST 시각을 붙입니다.

최신 잔고 뒤에 기록된 반복 체결 스냅샷은 해시·키·이전/현재/원장 경제값·비투영 여부를
모두 검증한 경우에만 새 경제 변경에서 제외합니다. 상한 확인 시각은 시세 관측시각과 분리하고,
실패 시 `capacity_diagnostics`에 구체적인 원인과 잔고 시각을 남깁니다. 과거 raw 페이지는
감사 근거로 보존합니다. raw snapshot 캐시와 종료일 경제 메타데이터 캐시는 구분하며,
종료일별 전체 raw 트리를 계속 보유하지 않습니다. 원장 WAL 전환·raw 페이지 삭제는
이번 변경에 포함하지 않습니다. 장중 당일 작업 우선, 명시 보호창 09:00~09:05·15:20~15:30,
단계 시간·바이트·RSS와 상태 게시, `limit_blocked`의 비금융 의미는
[종료일 재대사 성능 계약](docs/CLOSED_RECONCILIATION_PERFORMANCE.md)을 따릅니다.
검증·커밋된 취소 정산의 공개는 전용 경로로 장중 보류를 우회하되, 관측 상한·원천 검증과
정산 공개 전 예약 해제 금지는 유지합니다. 설치 감시기 교체는 수신기 배포와 별도 제안입니다.

EXP_D가 개장 청산창을 놓친 경우에는 원래 배정·소유세대를 유지하는 `late_recovery_exit`
소스 경로를 사용합니다. 보유 청산을 후보 선정 앞에서 처리하고 실제 현재 시각·공식 정규장과
통합 미체결·보유·00 증거를 다시 확인합니다. 정상/지연 청산과 재시작 사이의 중복 전송을 막으며,
늦은 매도를 09:00 신호나 시초가 체결로 소급하지 않습니다. 자세한 조건과 운영 미반영 경계는
[EXP_D 지연 청산](docs/EXP_D_LATE_EXIT_RECOVERY.md)을 따릅니다.

장후 보고서는 실제 `broker_observations.payload_json`의 출처와 해시를 검증합니다. 레거시
S5 관측에 없는 신호시각·키·가격은 추정하지 않고 미확정으로 분리합니다. 공식 Toss 캘린더는
예정 정규장 종료 경과의 증명이며 확정 종가·비용의 증명은 아닙니다. 원문 파일 SHA와 wire SHA는
각각 보존합니다. JSON 저장 후 재로드해도 TXT 표시 순서와 게시 검증이 같아야 합니다.

이 문서는 소스 계약입니다. 실제 실행 버전·배포 여부는 별도 배포 보고서로 확인합니다.

공유 40자리 안에서 미사용 S5 2자리와 해당 건당 예산을 다른 arm의 신규 매수로부터 보호합니다.
S5는 실제 관측 봉·현재 5분 경계·위험 증거를 주문 직전에도 다시 검증하며, 누락 봉을 만들지 않습니다.
활성화는 신호나 체결을 보장하지 않습니다. 세부 조건 실패와 미주문 사유는 각각 기록합니다.

### 2026-11-03 추가 수리 소스 계약

부분 체결 사이의 스트림 공백 때문에 정확한 손익 귀속을 복원하지 못하더라도 보호 청산은
별도 `exit_only_broker_confirmed` 증명으로 판단합니다. 당일 90초 이내 현금 보유 수량·매입금액,
완전한 전체 거래소 주문 내역의 봇 주문 일치, 통합 미체결 없음, 새 공백·외부 주문 없음이 모두
검증되어야 합니다. 예약과 전송 직전에도 다시 확인하며 수익 귀속은 미확정으로 보존합니다.
첫 체결 시각이 입증되지 않으면 타임스톱 시계를 만들지 않습니다. 증명이 부족하면 보호 청산
비활성 상태와 확인된 수량을 알립니다. 사용자가 `sell protect 6자리종목코드`를 직접 보내면
새 브로커 대사를 통과한 매도가능 수량만 시장가 청산하고 `manual_protective_exit`로 기록합니다.
이 수동 청산을 기존 arm의 확정 수익으로 바꾸거나 새 활성 arm으로 추가하지 않습니다.

재기동 없는 다음 거래일에도 공식 개장 구간과 장후에 각각 한 번 이전 주문일의 전체 주문내역과
당일 통합 미체결을 재대사합니다. 사용된 단계 claim은 재사용하지 않으며 페이지 누락·응답 유실은
미확정으로 유지합니다. 검증된 소멸 잔량 증명은 불변 기록으로 남겨 90초 경과만으로 되살아나지 않게 합니다.

과거 완료일의 경제값이 세 차례 연속 같으면 저장된 공식 달력의 다음 거래일 장 마감까지
추가 조회를 늦춥니다. 실제 확인된 7거래일을 넘고 미해결 주문이 없는 날짜는 자동 조회를 멈춥니다.
동일 REST 응답 본문은 원본과 작은 반복 관측 증명으로 나누어 저장하며, 재조회 시각·페이지·출처
해시를 검증해 읽습니다. 00 단위 체결과 기존 감사 이력을 삭제하지 않습니다.
SQLite는 원본입니다. WAL 전환과 과거 JSONL 이동은 [별도 승인 계획](docs/LEDGER_STORAGE_MIGRATION_PLAN.md)입니다.

실전 자동매도는 소유 어댑터가 구현되기 전까지 거부합니다. 실험을 끄면 저장된 레거시 설정을
곧바로 실행하지 않고 `stts`에 재개 대상과 확인 토큰을 표시합니다. `stts legacy confirm 토큰`으로
현재 설정을 명시 확인해야 재개합니다. S2~S4의 실험 보류와 레거시 저장 설정은 구분해 표시합니다.

장전 일봉은 08:30~08:55의 원래 관측시각과 공식 이전 거래일을 유지합니다. ORB 상대거래량은
저장된 직전 14세션의 실제 09:00~09:04 분봉으로 계산하며 부족하면 확보 세션 수를 남기고 보류합니다.
일봉 거래량이나 가짜 분봉으로 채우지 않습니다. 장후 입력 보고는 실제 저장된 선정·진단만 사용합니다.

위 변경은 승인 대기 중인 소스이며 현재 수신기에 자동 적용되지 않습니다. 배포에는 당일 전체 APP
격리 테스트·소스 manifest·백업과 공식 장 마감 후 별도 승인이 필요합니다.

### 2026-11-03 추가 외부 점검 후속 계약

지원 배포기는 `--code-approval`로 소스 SHA·대상 PID·당일 공식 세션·사용자의 코드 배포 승인을
검증합니다. 재시작 승인만으로 코드를 교체하지 않습니다. 정상 배포는 KST 화·목의 08:30 미만
또는 15:40 이후이며 공식 세션 밖이어야 합니다. 화·목 각각 하루 1회 시도만 허용하고 실패·미확정도
횟수를 소비합니다. 그 밖에는 별도의 짧은 유효기간 코드 승인 토큰이 필요합니다. 복사 중
승인이 만료되면 runtime 교체 직전에도 중단합니다. 과거 WORK 일회성 배포 CLI는 폐기되어
`RETIRED_USE_GUARDED_CODE_DEPLOYMENT`로 거부됩니다.

00 재개 이벤트 저장 실패는 예외 종류·비밀값을 제거한 원인·KST 시각을 남기며 다음 주기에
저장을 다시 시도합니다. 기록 오류는 최초와 미해결 10분 간격으로 알립니다. 유지보수 마커는
유효기간을 검증하고 공식 장전 08:50~08:59에는 현재 세대와 마지막 수명 이벤트를 확인하여
기존 모의 대사 경로로 복구합니다. 계정 수집기는 연결 시간초과 후 같은 프로세스에서 지수
백오프로 재연결합니다. 작업자 plist 변경은 템플릿만 준비하며 설치는 별도 승인 사항입니다.

새 배정의 `prospective_daily_control_floor_v2`는 R/A 목표 각 15% 이상을 실제 배정 수로
검증합니다. 과거 배정·성과는 바꾸지 않고 기존 1/6 목표와 14개 arm을 유지합니다. 신호에는
기존 테마 매핑의 버전·출처·미분류 사유를 보존합니다. S5는 공시/공매도/자료 부족의 실제
차단 사유를 분리하며 이 진단 변경으로 위험 보류를 해제하지 않습니다. 14세션이 부족한 ORB는
대체 일봉 규칙 없이 기다립니다. 이 후속 계약 역시 배포 전 소스의 동작 설명입니다.

안정 KPI·감시기·핫리로드의 준비 범위와 차기 처리량 프로필은
[안정·처리량 단계별 계약](docs/STABILITY_THROUGHPUT_ROADMAP.md)을 따릅니다.
새 60보유·10만원·100/80풀·변형 arm은 현재 v1 설정에 적용하지 않습니다.
